# 01 · 愿景与范围

## 1. 一句话

**一条 AI 肥鱼的多通道陪伴系统**：在 B 站直播弹幕、B 站评论、B 站私信、QQ 上与用户互动，
有共享记忆、有人格一致性、能 7×24 无人值守运行。

## 2. 为什么做

现有实现（dsh-bili-whale 插件链）能跑，但：

- 强耦合 DSH 会话 API，换大脑困难
- 四通道各说各的，私信与弹幕互不知情
- 记忆靠散落文件 + 模型自觉写
- prompt 拼装与调度逻辑纠缠在 1000 行里

自研目标不是「多一个功能」，而是**换一套能长期演进的架构**：
事件驱动、接口解耦、记忆独立、可观测。

## 3. 用户与场景

| 用户 | 场景 |
|---|---|
| 主人（项目所有者） | 电脑边用边跑；鱼替他在直播间互动、回私信 |
| 直播间观众 | 发弹幕，得到一条「像人」的鱼回复 |
| 私信 / 评论者 | 收到有记忆、有连续性的回复 |
| QQ 好友 | 在 QQ 里和同一条鱼聊天 |

## 4. 范围（In Scope）

| 模块 | 内容 | 阶段 |
|---|---|---|
| 看直播间 | 在线状态、实时弹幕、送礼、识图看画面 | P0/P1 |
| IM | B站弹幕回复、B站评论、B站私信、QQ 发言 | P0/P1/P3 |
| 记忆 | 共享事件、提炼记忆、归档、定时总结发动态 | P0–P2 |
| 人格 | 人设包化、跨通道一致、回归测试 | P0 |
| 成本 | 预算、分级模型、账本 | P0 起贯穿 |
| MCP | 对外暴露工具给外部 agent | P6 |
| 玩游戏 | SMAPI mod + 决策循环 | P7 |
| 开播 | 虚拟形象渲染 + 互动 | P8 |

## 5. 非目标（Out of Scope）

- ❌ 多实例分布式 / 集群
- ❌ 平台协议破解（协议端永远用现成的 NapCat/LLBot）
- ❌ 通用聊天机器人框架（只服务「养鱼」这个产品）
- ❌ 支持十种 IM 平台（先 B站 + QQ）
- ❌ 自研 LLM

## 6. 成功标准

| 维度 | 标准 |
|---|---|
| 可用 | Phase 0 后，直播时连续 2 小时稳定回复，不漏、不重、不崩 |
| 人格 | 回归集通过率 ≥ 90%，跨通道语气一致 |
| 记忆 | 重启不丢；能回忆 7 天前的对话；私信不泄露到公开通道 |
| 成本 | 日预算可控，有账本；超支自动降级 |
| 可靠性 | 静默失败（活着但不回）能被检测并告警 |
| 安全 | 凭据不落日志；公开/私密硬隔离 |

## 7. 关键约束

- 单机运行（用户个人电脑），内存预算 < 1GB（不含 Docker Desktop）
- 用户会用电脑做别的事，服务必须低干扰
- 开发期边用边改，需要热重载与一键启停
- B站/腾讯风控不可控，设计必须能降级、能重连、能补漏
