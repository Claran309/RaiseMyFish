# Change Note: 评分语义修正与候选人格对照

## 1. What Changed

新增persona-lexical-v3，区分第三人称提及主人与直接称呼当前用户，并修复六类低风险词法误报；保留v1/v2快照。独立候选personas/dafeiyu-v2/按批准清单整理，原包七文件不变。

规则完成后才冻结候选，真实B只跑原35条一次。v3为25/35=71.4%，v2同输出17/35，v1同输出15/35；按同一v3比较旧人格基线30/35，新候选没有改善。未达32，停止，H未读未运行。

## 2. Why This Change Was Needed

原“喊主人”只是搜索两个字，把“这得问主人”这样的第三人称授权也当成称对方主人。其他标签也把自然表达误当失败，例如有害羞态度却没固定语气词、承认没跟上却没固定兜底词、普通空行被判列表。

判断器修正与人格改进必须分开证明。先把旧输出用新标准离线计算，再用同一标准比较候选，才能避免把换尺子当成模型变好。

## 5. Key Code Concepts

**提及与呼语。** “问主人”提及第三方，“主人，你来决定”直接称呼当前对象。v3用有限直接呼语/身份认定模式，不因整句含“问主人”就放过后面真正的直接称呼。这仍不是通用语义理解，人工必须检查身份边界。

**条件Any。** 认身份只有在明确问身份时要求字面自称，普通“最近怎么样”无需每句报名字。条件只作用于该Any，不绕过forbid、长度或安全检查。字段omitempty使旧规则序列化字节不变。

**版本化测量。** 旧三轮v3分别23/35、30/35、26/35；这些是数学重算，没有新模型调用。新候选25/35只应与旧人格同v3的30/35比较，不与旧v2的57.1%直接相减。

## 6. Important Implementation Details

v3只改七标签；长度20和各场景hard上限、凭据检测/实际敏感值脱敏、承诺、辱骂及CP红线保持。真实中文列表仍拦，空行不拦；逗号后的主人身份认定与混合直接呼语已补先红后绿测试。

候选普通闲聊默认一句尽量20字，明确拒绝内部信息，不把授权请求与密码索取混同；身份未知不认主人，不凭爱好编当前活动。20条新示范与审批一致，原包只读；不改context.go、不注入K0。完整system12990字节，35条真实输入全部未裁剪。

评估没有增加多对照CLI功能：既有接口自动同输出v2，完成后rescore给v1，三套规则先于请求冻结，对照不增加调用。每个目录独占创建；初稿和最终v3离线证据都保留，不覆盖历史。
