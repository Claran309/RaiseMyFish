# 变更说明：提交0.1并确认人格加载接口

## 1. 改了什么

0.1按DSH验收快照提交为364dcb3并推送master。后续单独增加Persona Pack契约P0-PACK-1、WorkBuddy的0.7b放行单和YAML依赖；同步任务勾选、看板和README。

## 2. 为什么这样处理

验收过的代码应保持可追溯。强杀观察先明确现有心跳语义，避免在提交时悄悄变更已验收的功能；新依赖和下一任务接口放在单独提交，区分已经可用的基础设施与尚待实现的加载器。

## 3. 文件职责

- contracts/persona.md：固定Pack/Meta字段、Load与纯访问函数、YAML/文本校验、场景映射和测试要求。
- plans/phase-0.7b-dispatch.md：列明WorkBuddy可改文件、草稿留存位置、禁止越界项与交接方式。

- plans/phase-0.md、coordination.md和Codex报告：记录0.1完成事实、PID观察裁决、Pack放行和未确认回执。
- README、docs/08-persona.md、contracts/README.md：补状态含义及接口入口。

## 4. 接下来的流程

主人授权 → 0.1快照复核并提交 → Pack契约与依赖准备 → WorkBuddy确认接手并实现0.7b → DSH独立验收 → Codex集成。回归执行器和真实模型评测仍等待0.6，不在加载器任务中提前实现。

## 5. 关键概念

接口基线规定多个开发者共享的数据形状与失败语义。Brain需要的是persona.Pack值，因此加载器返回相同的数据类型；加载、动态上下文组装和模型调用分别负责，不让一个轻量任务跨越三层。

心跳反映最近一次健康观测。强杀后旧文件短时间仍有效，这是当前检查的时效边界；service.state属于最后记录，service_alive才是经过时效和数据库判断的结果。

## 6. 边界与取舍

本轮不追加单独PID检测：PID可能复用，存在不等于同一fishd。0.11再设计实例身份增强；默认20秒时效不变，运行时代码未修改。

Pack仅含稳定人格；场景键qq_private/qq_group不是新的Event.Channel。短的非空文件有效，不接受草稿里未经文档确认的最低字数门槛。YAML交给维护中的解析库，不维护自写子集。

旧0.7c草稿不删除；WorkBuddy可按放行单原样留存在忽略点目录，避免其旧API参与0.7b编译。此处只是派发约束，本轮没有移动或改写草稿。
