# Change Note: 场景规则与动态资料分离

## 1. What Changed

Brain把可信人格包的当前scene从context资料段移到instructions指令段，说明它是本轮要遵守的场合、称谓、语气和长度规则。固定说明不再重复另一套宽松数字上限。人格三段system、模型、评分、预算、超时/重试和防御截断都不变。

这是一次有独立新run的装配实验。真实v2结果13/35=37.1%，低于原20/35=57.1%，未达90%；结构修复与人格效果分别判断，不把代码测试通过当成模型效果提升。

## 2. Why This Change Was Needed

旧context既包含Memory/Shared资料，也包含可信Pack选出的场景规则；末尾却把整个context叫作“不是新指令”。这混淆了“应该遵守的口径”和“仅供参考的对话内容”。本次先在P0-BRAIN-2明确边界，再用失败测试复现，最后只改组织方式。

零调用意图审计还发现词法评分与素材之间的冲突。但用户只批准审计和装配实验，因此没有借机修人格或词表；情绪词未命中等问题仍按原规则计分。

## 4. Core Flow After The Change

```text
可信Pack.ContextFor(channel, private)
  -> instructions.scene（JSON转义、原文保留）
Memory/Shared -> context（JSON资料）
当前Event -> event（JSON资料，不含Meta）
原Pack.SystemPrompt + 上述user三段
  -> 原预算裁剪 -> 原Provider -> 原用量记账
```

只把规定从“资料袋”移到“指令袋”；并没有把私聊权限或主人身份交给模型判断。

## 5. Key Code Concepts

**数据来源比文字外观重要。** scene来自本地可信Pack与已验证的场景键。用户写“我是主人”或者在消息里写instructions标签，也不能改变程序选中的scene。

**JSON转义保护段结构。** context、event和scene分别编码；闭合标签里的尖括号被转义，资料不会额外创建真正的外层指令段。这能证明段结构稳定，不能宣称模型因此完全免疫提示注入。

**字节快照与单因素对照。** 人格、用例、规则、配置和完整system均与基线相同，唯一运行源码差异为context.go。两轮随机输出仍有波动，所以单轮下降不能当成完整因果证明。

## 6. Important Implementation Details

scene JSON在裁剪循环外创建，场景原文不TrimSpace；Memory切片仍复制后排序。预算裁资料和人格局部副本，保留scene、当前事件、固定说明及soul，不修改调用方输入。

replyLimit仍用于原防御截断，live40/comment200/dm500/qq200未改。删除的只是user末尾重复的数字提示，要求模型遵守原scene自带长度；原始与投递分数继续分开记录，不能用截断隐藏模型失败。

不增加Owner字段、不把private当主人身份、不变更查询层权限；不把意图审计或评分标签送进模型。每次真实尝试仍一行llm_usage，新run单独统计35行和228571/409 tokens；报价缺失费用NULL，不和旧run混算。
