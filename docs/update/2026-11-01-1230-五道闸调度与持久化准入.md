# Change Note: 五道闸调度与持久化任务准入

## 1. What Changed

新增 Phase 0.4 调度器。它从现有事件总线领取事件，执行 ACL、噪音、幂等并发、节流、优先级五道闸，并把已获准的任务交给下游回调。生成和核验使用两个独立回调，不把补偿事件再次交给生成器。

本次还新增调度仓储：PG 检查会话中已入库的较早未结束事件，原子执行每日准入额度检查与任务写入。现有 Event/Memory 契约、迁移、人格和判断器不变；fishd 生产循环仍未接入调度器。

## 2. Why This Change Was Needed

总线解决了“谁领取了事件”，还不能决定事件该不该回复、什么时候执行、同一会话能否同时处理。直接对每个 Claim 调模型，可能让广告进入生成器、同会话并发、后到的点名抢在前文之前，或在恢复时重复扣额度。

现在调度状态由一个 Run 循环统一管理，PG 保存任务准入事实。单进程内的堆、会话锁与计时器负责执行顺序；数据库约束和事务负责跨重启的任务唯一性及每日额度。这两类状态承担不同责任。

- `internal/scheduler/types.go`：Options、每通道策略、Clock/Timer、Work、Result 与 Generate/Verify 回调入口。

- `internal/scheduler/run.go`：单循环生命周期、下游回调、结清代次核验、冷却、取消与退出。
- `internal/scheduler/scheduler_test.go`：五道闸、阶段恢复、时钟、并发/续租/回执边界及退出测试。
- `internal/store/scheduler.go`：新增调度仓储接口及准入/配额 DTO，不改现有接口。
- `internal/database/scheduler.go`：查询会话顺序、PG 通道/日事务锁、任务配额、代次快照。

## 4. Core Flow After The Change

```text
Notify / 定时轮询 / 冷却到期
  → 续租等待中与执行中的Claim
  → Recover + 有界ClaimPending
  → 优先堆
  → 校验ACL
  → schedule首次噪音/内容重复过滤
  → 事件去重、会话互斥、PG较早未结束事件检查
  → schedule冷却、令牌预留、每日准入配额
  → 同事务写唯一Task并切换generate
  → 启动前再次Renew并确认阶段/范围
  → Generate或Verify回调
  → 回调用Bus结清后返回
  → 复核持有代次、设置冷却、释放会话
```

恢复 generate 读取已有 Task；恢复 verify 不造 Task。二者不重复噪音过滤或扣首次准入额度，但仍遵守结构 ACL、会话顺序与持有权。

## 5. Key Code Concepts

**优先级与会话顺序**：堆决定哪个候选先被检查；同会话是否可以执行还要查 PG。即使后到消息来自可信主人，也不能越过该会话较早的未结束事件。跨会话则可以并发。对尚未到达数据库的迟到消息，系统无法预知；检查范围是已入库事实。

**令牌预留与退款**：x/time/rate 为新任务准入预留令牌。如果仍需等待、配额不足或准入失败，就取消预留，避免没有启动任务却消耗调度容量。已经持久化的任务恢复时不再购买首次准入令牌。

**持久化准入配额**：按通道、日界查询 tasks.CreatedAt。PG 事务锁覆盖计数、唯一任务写入及 generate 阶段切换；竞争者不能都读到同一个剩余额度。重建调度器不会清空任务账本。

**代次与结清回执**：正常终态或 Defer 会把租约代次从 V 加到 V+1，并清 Owner。调度器用这个事实区分正常释放与新持有者接手，不只看到 Renew 失败就丢掉工作结果。外代的新状态不能用于判断旧回调是否未结清。

## 6. Important Implementation Details

- 可信 Owner ID 按通道配置；正文自称主人不会获得 Owner 优先级。噪音支持 self/bot ID、广告片段、最小长度、纯符号和白名单；短时重复使用正文 SHA256 加会话/发送者键，不缓存去重正文。
- 会话键为 Channel/Session。锁从派发保持到回调真正返回；丢租只先取消回调，不提前解锁。回调须响应 Context，不能在取消后继续使用旧 Claim 操作平台。
- 队列有容量上限，默认 100、默认并发 4；等待中的 Claim 同样续租。每次启动回调前重新 Renew，避免仓储查询耗尽租期后仍开始生成。
- 回调必须经 Bus 持久化终态或 retry，再返回。当前代仍持有且未结清会报 ErrUnsettled；未分类错误或 panic 使 Run 失败，不在调度器中无限重试模型。
- 正常释放与续租交错时保留结清回执；即使回执晚于更高代接手，Replied=true 也只会保守收紧本地冷却，不改新持有者的数据库状态。
- 冷却使用 time.AfterFunc，经 Clock 注入可在测试中推进时间。到期记录会清理，退出时停止计时器；回调只发送合并唤醒，不并发修改调度 map。
- 日界默认 UTC，可注入 Location；用日历 AddDate 切到次日，夏令时回退日可以是 25 小时。
- **每日配额是新增 Task 准入数，令牌是准入速率，不是实际发送数或平台发送间隔。** 冷却、令牌、短时内容去重是单进程内存态；实际发送的持久化频控与额度衔接留 0.8/0.11。这里没有把后续功能宣称为已交付。
- 本轮没有迁移或生产配置修改，没有模型/平台调用。回调使用合成实现验证任务生命周期，不是实际人格或平台验收。
