# 变更说明：0.7c真实人格评估与证据

## 1. 改了什么

0.6按DSH已验收快照提交并推送b51f444。新增personaeval评估器和fishctl persona eval，使用.env真实密钥调用配置的模型，完成35条实际用例；生成逐条原始输出、Brain投递文本、评分、源码/人设/规则/用例快照、逐次调用审计与PG核账。

本轮结果是15/35=42.9%，未达到90%；评估器新代码与产物尚待DSH独立复核，没有把功能执行完成标成退出标准已达成。

## 2. 为什么这样实现

真实模型测试需要把输入、规则、模型与输出放在同一条证据链里。只打印通过率无法知道是否换过样本、用过baseline或靠截断掩盖长句，因此评估器在首次调用前冻结规则与输入，每条落检查点，并将原始输出作为主分数、投递文本作为次分数。

## 3. 文件职责

- internal/personaeval/score.go：冻结persona-lexical-v1词法规则，不读取基准回复。
- internal/personaeval/fixture.go：读取实际35条JSONL和五个人格文件，核验Load前后哈希一致。
- internal/personaeval/run.go：证据目录独占创建、规则/用例快照、逐条同步检查点、两套评分及完整性判断、敏感值脱敏。
- cmd/fishctl/persona_eval.go：构造真实Provider/Brain与PG UsageRepo，合成每条独立Scope，审计prompt哈希、原始模型输出、服务端model与账本确认。
- internal/brain/provider/：仅加可选Model审计元数据；请求、正文、重试和计费逻辑不变。
- contracts/persona-eval.md及实际run目录：执行规则与本轮证据；没有修改personas人设正文、cases或baseline。

## 4. 执行流程

先验证全部用例/标签 → 固定规则/人格/源码hash → 保存用例和规则 → 每条新建Task/显式空记忆Scope → 真实Brain/Provider调用 → PG逐次记账 → 原始/投递分别评分 → 同步results.jsonl → 汇总report.json/report.md。expect/forbid/kind不在生成器输入里，baseline不是运行输入，也没有baseline回放后端。

## 5. 关键概念

**请求模型与服务端模型标识分开**：本轮配置请求deepseek:deepseek-chat，35次服务端均返回deepseek-flash；两者都记录，不猜测内部版本。

**数学分数与运行完整性分开**：失败不从35分母删除，整轮取消或鉴权/记账致命失败即使发生在最后一条，也不能报告完整验收成功。新增末条错误/取消测试实际复现了该边界，再修复通过。

**自动词法分数有边界**：例如拒绝句「不给。密码这种东西哪能往外掏。」因词“密码”命中泄露标签。这个解释不改变本轮分数；如果改词表，必须另开规则版本/run，不能覆盖真实失败结果。
