# 变更说明：K0 知识快照与只读迁移

## 1. 做了什么

新增独立的 `internal/knowledge` 包：定义知识范围和只读上下文，加载严格校验的文件快照，按权限、场景和关键词召回最多3条。迁移工具从本地 SQLite 只读导出全部原始记录，经过显式审核清单后生成首批500条梗知识。

这是 K0-1～K0-4 的模块交付。知识尚未接入 Brain，`ContextInput` 没有在本轮修改；预算注入、真实模型对照和100条自然检索质量验收留给后续步骤。主人已明确接受当前P0现状，允许本模块与主对话的人格优化并行。

## 2. 为什么需要这次改动

人格决定怎么说，知识提供可引用的资料，记忆保存有交互来源的事实。把梗库全部塞进人格，会增加静态prompt并让资料与规则混在一起；把梗伪装成记忆，又会污染“谁说过什么”的来源。

现在知识可以独立加载和验证。文件名随人格目录组织，但代码不依赖人格、记忆或Brain实现；本轮也不增加数据库表、向量模型或网络服务。

## 3. 主要文件

- [types.go](../../internal/knowledge/types.go)：Scope、Query、Item、Context和Reader契约。
- [validate.go](../../internal/knowledge/validate.go)：通道、场景、来源、版本及同私密会话检查。
- [file.go](../../internal/knowledge/file.go)：白名单文件、严格YAML、资源上限和原始字节Revision。
- [recall.go](../../internal/knowledge/recall.go)：先过滤后匹配、稳定排序、Top3与返回副本。
- [export-memes](../../scripts/export_memes.py)：只读快照、分层候选、人工审核要求和无覆盖发布。
- [公开知识目录](../../personas/dafeiyu/knowledge/memes.md)：500条原词和原始接法；另外三个根文件保持空条目，没有编造观众或世界观素材。
- [正式交接目录](../../plans/reports/knowledge/20261031-k0-first-500-final/handoff.md)：开发自测、源数据/审核清单、独立核对和文件快照入口。

## 4. 改动后的流程

```text
本地源SQLite（只读事务）
  → 原始JSONL快照与内容hash（data/，不入仓）
  → 分层候选清单（默认全部未审核）
  → 明确审核的500条ID
  → memes.md + 发布manifest
  → FileReader构造时完整加载并校验
  → Recall(可信Scope, 消息正文)
  → 权限/场景过滤 → 词匹配 → 稳定排序 → 最多3条副本
```

流程停在候选知识。实际prompt序列化、<=15%预算和模型调用不在本轮实现。

## 5. 关键概念

**Scope是范围，不是身份。** 私聊标记只说明目标会话私密，不能证明对方是主人。私密条目必须带来源Scope，且只能回到相同通道和相同会话；公开条目也必须符合声明的场景。

**快照是一次实际读取的内容。** Revision按相对路径排序，将每个文件的原始字节hash再次汇总。移动整个目录不改变版本，改CRLF/BOM也会改变版本。解析时允许规范化换行，但不能用规范化文本冒充原始文件hash。

**幂等是重复执行不改变结果。** 同一个源快照和审核清单应生成相同字节。相同目标不重写，目标被人工修改则失败，不能直接覆盖。源库的同名custom覆盖内置层，但两个原始记录仍都留在归档。

**校验不是过滤的替代。** Reader在匹配和统计之前过滤权限；Context.Validate再检查调用边界。未来结构化表须在repository/SQL里过滤，不能先把其他私聊资料读出来再靠prompt控制。

## 6. 重要实现细节

四个根文件都必需，后续梗文件仅接受 `memes/batch-*.md`；其他文件不扫描。单文件1MiB、单条16KiB、全库32MiB/10000条；还检查链接不能逃出根目录。文件读取、解析遍历和单条多触发词匹配都检查取消，没有后台goroutine。

YAML既用KnownFields，也检查节点类型，因为yaml.v3可能把数字自动转换成string。锚点、别名、合并键、重复字段、未知字段和多文档整体拒绝；错误不回显正文。来源首尾空白同样拒绝，避免把“带空白的绝对路径”误当安全引用。

标题、keywords、有效标签按等级排序，再比较最长命中、不同命中数、priority和ID。泛分类如文字梗、游戏梗、网络用语、直播不单独触发；重复词不增加权重，英文有单词边界。返回slice与Origin复制，修改结果不污染并发请求的快照。

首批审核查看775条，排除265条，固定启用500条。只启用原title和usage；summary、origin、other等全部原始字段留在本地归档，不用于首批资料。这保留数据，同时避免将未核实的百科出处放入上下文。审核是开发侧素材筛选，不替代DSH独立验收，也不代表自然查询相关率已达80%。

只读审查指出两项问题并经失败测试复现后修复：来源前导空白绕过，以及发布端漏算tags等字段。现在发布前按Go同口径检查完整条目大小，超限整批失败、不留下输出；只读审查已复核关闭两项。

## 7. 如何验证

本轮全仓单测、真实PG集成、vet、build、lint、WSL race均通过；Python6项测试通过。知识包一次覆盖率检查为90.2%；500条逐一用自己的原词查询均能召回对应ID，这只证明字面召回完整，不等于自然检索质量。

```powershell
go test ./... -count=1
go test -tags=integration ./... -count=1
go vet ./...
go build ./...
go run github.com/golangci/golangci-lint/v2/cmd/golangci-lint@v2.15.0 run ./...
wsl --cd /mnt/d/CodeStudy/RaiseMyFish --exec env CGO_ENABLED=1 /usr/local/go/bin/go test -race ./... -count=1
python -B -m unittest discover -s scripts -p test_export_memes.py
python -B plans/reports/knowledge/20261031-k0-first-500-final/verify_migration.py
git diff --check
```

PG回归验证的是既有数据库路径，本模块没有写SQL；假HTTP→知识→Brain→PG的新增组合验收随K0-5以后完成，不能把本轮PG全绿当作那条链路已经接好。
