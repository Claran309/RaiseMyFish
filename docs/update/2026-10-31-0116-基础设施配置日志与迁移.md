# 变更说明：Phase 0.1 基础设施

## 1. 改了什么

本轮从纯文档仓库建立Go模块和两个入口：fishd可连接PG、检查迁移、持续探活并优雅退出；fishctl可查看状态和跟随日志。配置、日志、连接管理、SQL迁移、测试与CI一起落地。业务采集、Brain、调度和发送尚未实现。

## 2. 为什么这样设计

后续模块需要一个可信的运行地基：配置不能泄漏密钥，数据库结构不能依赖手工创建，程序不能「进程还在但数据库已经断开」。因此配置加载、基础设施生命周期和迁移各有独立边界；迁移显式执行，普通启动不改库。

已有文档锁定GORM/pgx和zap，本轮直接采用；内部模块不新增HTTP服务，状态通过本机文件及数据库探测判断。已存在但未验收的人格Go代码保留原样，未作为本轮依赖接入。

## 3. 文件职责

- `go.mod`、`go.sum`：模块名RaiseMyFish，最低Go1.25，锁定实际依赖。
- `internal/config/`、`config/fishd.toml`：加载TOML、本地dotenv、环境覆盖及基础设施校验；不要求尚未启用的LLM/B站凭据。
- `internal/database/`：GORM/pgx连接、PG17检查、事务迁移和就绪检查；底层错误保留错误链但展示时隐藏连接细节。
- `migrations/`：初始7张业务表和6档来源种子，作为二进制资源嵌入。
- `internal/infra/`：PG Setup/Close、单实例advisory锁、JSON双输出日志、日期滚动与7天清理、本机原子状态写入。
- `cmd/fishd/`、`cmd/fishctl/`：入口装配和信号取消；status/tail不查询业务消息正文。
- `.github/workflows/ci.yml`、`.golangci.yml`：修复checkout前的空仓检查，固定Go1.27/lint2.15.0并启用PG17集成job。
- README、模型/部署/测试文档：记录已实现命令和仍属于后续阶段的配置。

## 4. 运行流程

```text
TOML默认值 → dotenv → 进程环境覆盖 → 校验
fishd migrate up → PG17连接 → 事务锁 → SQL/种子 → checksum账本 → 提交
fishd → 连接/迁移检查 → 单实例锁 → 状态心跳与PG探活
Ctrl+C/SIGTERM → 取消循环 → stopped状态 → 释放服务锁/连接池/日志
fishctl status → PG/迁移探测 + 心跳时效 → JSON摘要与退出码
fishctl tail → 当日日志 → 追加跟随 → 跨日切换 → 取消退出
```

## 5. 关键概念

**迁移事务**：七张表、种子与账本在同一事务里成功或回滚，避免只建了一半的库。

**checksum**：把SQL内容算成SHA256并记录，重复迁移时验证。代码与库的迁移历史不一致就报错，不能用IF NOT EXISTS把漂移掩盖过去。

**advisory lock**：PG提供的显式锁。迁移用事务锁防止并发建表；服务用连接持有的锁拒绝同库/schema第二实例。关闭连接池前显式释放锁；退出上下文已取消时仍用有上限的清理上下文。

**状态文件不是永久在线证明**：只有running、数据库就绪、正PID且心跳未过期时才显示在线；进程崩溃留下的文件会超时，正常停止则写stopped。

## 6. 实施细节与边界

配置优先级为进程环境 > dotenv > TOML > 默认值，包含显式空变量的优先级；dotenv不会写入全局环境。日志不打印完整配置、DSN或密钥；数据库错误展示脱敏但保留Unwrap链。

普通启动不自动迁移，不提供破坏性的初始down。所有通道默认关闭；0.1误开通道直接报错，避免空实现假装健康。当前状态接口只报告基础设施，不能代表鱼已能回消息。

测试使用随机schema并只清理自己的schema；没有改PG监听、防火墙或已存在业务数据。真实目标库仅应用了显式初始迁移与来源种子。

Windows现有GCC为32位，无法编译amd64 race；便携64位编译器下载超时，未安装/执行该下载。改用已有WSL Ubuntu的Go1.25，安装gcc/libc6-dev测试依赖（apt同时更新其libc相关依赖）后运行race，未修改Windows PATH。WSL不能直连Windows localhost PG，因此本机race和真实PG分别验证；Linux+PG17组合由CI实际运行，尚未宣称远端CI通过。

## 7. 验证证据

Windows执行通过：

```powershell
go test ./... -count=1
go test -tags=integration ./... -count=1
go vet ./...
go build ./...
go run github.com/golangci/golangci-lint/v2/cmd/golangci-lint@v2.15.0 run --build-tags integration ./cmd/... ./internal/config/... ./internal/database/... ./internal/infra/... ./migrations/...
go run github.com/rhysd/actionlint/cmd/actionlint@v1.7.9 .github/workflows/ci.yml
go run ./cmd/fishd migrate up
```

迁移重复执行、并发执行、外键/索引/种子、checksum篡改拒绝、同名表冲突后事务回滚全部通过。编译后的Windows程序真实启动、status健康、第二实例拒绝、tail跟随、Ctrl+C退出0与stopped状态验证通过。

WSL Ubuntu22.04/Go1.25执行 `CGO_ENABLED=1 go test -race ./... -count=1` 通过。Windows32位GCC race失败和WSL→WindowsPG组合连接失败均是已记录环境限制，不以普通test结果代替该组合结果。

上述是Codex实施自测。DSH需对冻结快照独立验收后再提交/push；本轮未把0.7b或整阶段退出标准标为完成。
