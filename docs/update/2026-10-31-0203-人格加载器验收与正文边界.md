# 变更说明：接收0.7b并保留场景正文

## 1. 改了什么

接收WorkBuddy交付、DSH验收的五个人格加载器Go文件及meta.yaml过时注释清理。Codex按本轮授权补三个回归测试，修正场景正文首尾空白被删的问题，执行go mod tidy将YAML库整理为直接依赖；没有接入Brain、CLI或真实模型。

## 2. 为什么修正文边界

契约要求保留正文。问题不在ContextFor：它已直接返回map中的值；上游splitContexts在flush时TrimSpace，提前删掉了正文首行缩进和边界空白。另一个循环会给原本没有行尾的正文补换行，也不符合保留原文的要求。

## 3. 文件职责

- internal/persona/meta.go：YAML结构化解码与元信息校验。
- internal/persona/pack.go：读取五份文件、取消/大小/编码校验、场景切分及纯访问函数。
- internal/persona/*_test.go：真实包、最小包、YAML/文本边界、场景/空白保留和纯函数测试。
- personas/dafeiyu/meta.yaml：只移除已过时的自写解析器说明，不改变字段值。
- contracts/persona.md：澄清独立场景标题、混合说明标题、正文与SystemPrompt的不同裁剪规则。
- go.mod：go.yaml.in/yaml/v3 v3.0.5成为直接依赖。

## 4. 修改后的流程

Load读取文本并统一编码/换行 → splitContexts移除独立场景标题行，保留其余原文 → ContextFor原样返回该段 → 后续Brain负责动态拼装和预算。SystemPrompt仍只对soul/rules/samples按契约TrimSpace。

## 5. 关键概念

判空与改写是两件事：strings.TrimSpace(body)==空可以用于拒绝空段，但不能把裁剪结果存回正文。保留行结束符的遍历还可以区分「原文有换行」和「原文没有换行」，避免解析器悄悄改内容。

## 6. 明确边界

`## live 补`作为普通正文接受；它不是独立ASCII场景键，不能切换到live。新增场景应写独立的`## live`。缺场景仍会被meta.channels集合校验拒绝。

本轮没有删除/接收旧0.7c回归草稿，它们仍在已忽略的.workbuddy点目录。DSH原始交付已验收；Codex的正文补丁是本轮裁决后的增量，不能描述成DSH已复验该增量。真实模型通过率仍等待0.6/0.7c。

## 7. 如何验证

先添加首尾空白、无末尾换行、混合标题和Load→ContextFor完整路径测试，观察到原实现实际丢失缩进/换行后再修正。针对性测试和全仓单测随后通过；真实PG integration、vet、build、lint、Linux race与依赖校验结果记录在Codex报告COMM-006。没有用baseline回放代替真实模型验收。
