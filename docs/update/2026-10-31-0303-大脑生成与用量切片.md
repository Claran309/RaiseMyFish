# 变更说明：Phase 0.6 大脑生成与用量切片

## 1. 改了什么

实现纯文本Brain、单次OpenAI兼容Provider、Memory最小DTO/范围校验、Event契约类型，以及写既有llm_usage表的repository。配置支持Provider/routing和按模型报价；fishd可装配Brain并通过check-brain做无模型调用诊断。运行通道仍关闭，没有真实召回/发送或人格eval CLI。

## 2. 为什么拆这些边界

Provider只负责一次HTTP请求，Brain统一控制次数、预算和取消，避免两层重试相乘。调用结果必须经过独立UsageRepo记账；即使正文不支持或调用超时，已经发生的尝试也不能消失。Memory数据带Scope，防止其他会话的私密内容进入模型；SQL过滤实现仍属后续repository/0.9。

## 3. 文件职责

- internal/brain/types.go、brain.go：接口/typed error、并发、总超时、重试、回复截断与每次调用记账。
- internal/brain/context.go：Scope输入检查、只读复制/稳定排序、结构化user段与保守预算。
- internal/brain/provider/：单次非流式HTTP、可信端点、禁重定向、大小上限、统计与正文分层解码。
- internal/memory/context.go：按P0-MEMORY-1定义DTO与纯校验，不实现数据库召回。
- internal/event/types.go：已有事件枚举/字段及枚举合法性检查，不实现总线/状态迁移。
- internal/store/usage.go、internal/database/usage.go：注入接口和GORM写入，未知token/费用保存NULL。
- internal/config/llm.go、config/fishd.toml：可选启用、路由/模型清单、环境覆盖、可空报价。
- cmd/fishd/brain.go及main接缝：统一构造具体实现，诊断不请求模型、不虚记账。

## 4. 生成流程

```text
可信Task/Event + 已加载Pack + 显式Context/SharedState
  → 总Context与并发槽
  → 输入大小、Scope、数据与人格校验
  → system静态人格 + user(context/event/instructions)
  → 预算裁剪
  → Provider一次请求
  → 有界UsageRepo记账
  → 成功则rune截断并返回；失败按类别/剩余总次数退避或退出
```

没有实际Provider调用的输入拒绝/预算拒绝/排队超时不产生虚假用量行。取消后已发生的调用用独立最多5秒清理Context记账；记账错误不被吞掉，也不再次生成。

## 5. 关键概念

**未知不等于0**：token/价格未返回或未配置时使用nil/SQL NULL。明确0价格才能表示免费；成本按服务端统计与配置报价估算到6位小数，prompt字节估计不能当作账单。

**静态与动态分离**：system只有soul/rules/samples；场景、记忆、共享事实和事件放user。段内JSON转义尖括号，平台Meta不注入。裁剪复制slice，不污染共享输入。

**范围校验不替代SQL**：Brain拒绝错配Scope、跨私密会话、误标公开的DM等输入；后续MemoryRepo仍必须在查询中硬过滤并用真实PG验收。这里没有靠prompt让模型自行保密。

## 6. 实施细节

默认prompt预算8192，估算为两条消息UTF-8字节数+64框架余量，保守但不是模型精确tokenizer。先裁低重要性记录和较旧消息/事实，再裁samples/rules后缀；soul、场景、当前事件不删，放不下就报错。输入另限4096条/引用与4MiB文本；准备过程在并发槽内并检查总Context，按类别二分裁剪，避免O(N²)全量重编码。

每轮最多3次实际Provider调用；空回复最多补1次且共享总次数。4xx含429、协议错误不重试；网络/超时/5xx可在剩余次数内重试。总/排队DeadlineExceeded退出本轮，但允许上层用新Context决策重试；主动Canceled不可重试。

只接受HTTPS或本机loopback HTTP，拒绝端点userinfo/query/fragment，不跟随重定向，响应上限2MiB，错误不回显响应体/密钥。完整JSON中的usage独立于choices正文解码，正文类型错误仍保留有效统计；无效JSON或计数保持未知。

价格按provider.prices.model配置，两项须同时存在；未报价就NULL。相同provider:model路由别名复用一个Brain/并发槽，不等同于未来scheduler全局并发控制。

## 7. 验证

先编写测试再实现：新类型/API最初以缺失符号产生编译红；审查增量有可运行的行为红→绿证据，包括总超时误判永久错误、准备阶段耗时不受限、超大输入未拒绝，以及正文类型错误丢失有效usage。没有把已有通过测试倒称为事前失败证据。

单测/真实PG integration/vet/build/lint、Linux Go1.25 race已通过。假HTTP→Brain→真实PG测试使用已接收的dafeiyu包，验证一次503后成功产生两条对应账本，未知费用NULL。真实CLI/PG的check-brain诊断通过，模型调用次数为0。

内部只读审查发现的3项Important均已补回归并修复；这不是DSH验收。DSH必须根据最终manifest与Brain/Memory契约独立重跑和检查。未调用真实LLM、未评估人格≥90%；Windows32位GCC与WSL直连Windows PG限制沿用既有记录，race与真实PG在本机分别验证。
