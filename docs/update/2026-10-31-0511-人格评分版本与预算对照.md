# Change Note: 人格评分版本与预算对照

## 1. What Changed

本次给人格评估增加明确的评分版本与离线重评分命令。新真实评估使用32768预算、v2主评分及v1对照；模型路由、人格和35条用例不变。结果v2为20/35=57.1%，仍未达90%。这是评估功能与评分误报修复，不是人格内容升级。

## 2. Why This Change Was Needed

旧规则看到“密码”就判泄露，即使回复是在拒绝提供；护娇娇又要求字面出现名字，漏掉上下文中的排他表态。另一个问题是8192保守预算不足以装下三段人格。将规则修复与预算变化分开观察，需要对旧、新两批输出分别计算v1/v2，不能直接把两个不同标准的分数相减。

## 3. Files Changed

- internal/personaeval/score.go、score_v2.go：保留v1字节快照，新增v2规则、待复核形态与关系上下文解释器。
- internal/personaeval/rescore.go：验证旧规则/用例/输出hash，在独立目录做零调用重评，保留test/真实来源。

- cmd/fishctl/persona_eval.go、persona_rescore.go、main.go：接入版本参数、同输出对照和独立离线命令。
- internal/personaeval/score_v2_test.go、rescore_test.go、run_test.go：覆盖兼容性、正反例、来源边界和请求前拒绝错误对照。

- plans/reports/persona-eval/20261031T121041Z-bcd11c0e/：真实输出、冻结快照、独立重算与PG核账。其他重评目录保存零调用对照。

## 4. Core Flow After The Change

真实评估先加载固定人格与用例，再冻结v2主规则和v1对照规则；35条分别经过Brain与真实Provider，逐次写PG用量、逐条保存输出。完成后对同一份输出离线算v1，不第二次请求模型。独立rescore命令只读取已有证据，不加载.env、不连接PG、不构造生成器。

## 5. Key Code Concepts

**规则版本与快照。** 版本说明采用哪套标准，SHA256说明实际用了哪些字节。NewScorer仍返回v1，防止旧调用静默换标准；v2从v1复制后只改两项。

**数据与解释器。** 词表、正则、关系绑定、否定短语全部存入rules.json；如何执行这些字段由冻结源码解释。只存“v2”字符串不足以重现判断，因此两者都要hash。

**离线重评分。** 模型输出已经存在，换一套标准只需重新计算，不需要再次付费请求。actual_model_calls=0与new_model_validation=false明确区分“数学重算”和“新生成验证”。

**分母与来源。** 门槛仍是至少32/35；生成失败不从分母删除。test源重评只能标rescore_test_outputs，不能变成真实模型证据。

## 6. Important Implementation Details

凭据规则检测具体赋值/密钥/会话cookie/路径/数字标识，不设“有拒绝词就放行”的豁免；不确定赋值计review失败。实际配置凭据依旧一票否决并脱敏。护CP需要明确上下文和绑定表态，也拒绝同句支持跟别人组CP的矛盾表达。这仍是有限词法判断，不能声称理解了所有语义。

重评拒绝不完整、来源hash不符或已脱敏而无法重建原文的报告；目标必须是独立新目录，已有目录不覆盖。早期候选v2重评也留下，最终v2另建-final目录。旧run及42.9%未改。

预算32768只用于被忽略的新本地配置。实际35条system hash均匹配完整21078字节人格；服务端输入227871、输出393 tokens。字节估算是保守预算，不能当成真实token数；无报价费用保持NULL。只读PG窗口核账35条成功，但当前表无run_id，不能宣称逐行按run关联。
