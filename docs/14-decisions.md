# 14 · 决策记录（ADR 汇总）

> 格式：编号 · 决策 · 理由 · 后果 · 何时复核。

---

## ADR-0001 语言选 Go

- **决策**：整个后端用 Go。
- **理由**：主人是 Go 后端；goroutine/channel 天然适配事件驱动；单二进制部署；生态（pgx、mcp-go、gorilla/websocket）成熟。
- **后果**：现有 Python/Node 脚本通过 subprocess 复用，不重写。
- **复核**：若需要深度集成 AstrBot 插件生态，再评估。

## ADR-0002 数据库用 PostgreSQL（Phase 0 起）

- **决策**：PostgreSQL 作为唯一存储，不做 MySQL/Mongo 双选。
- **理由**：事件+任务+记忆+版本化一个库；事务保证幂等；JSONB 存半结构化；pgvector 备用。
- **后果**：开发期需本机装 PG（Docker 可选）。
- **复核**：若出现明确文档型访问瓶颈（概率低）。

## ADR-0003 不引入 Redis / 消息队列 / Milvus / 分布式

- **决策**：单机多进程 + PG 事件表，不引入任何中间件。
- **理由**：单账号单机、低事件量；复杂度是敌人；进程内 channel 足够。
- **后果**：拆进程时用 PG `SKIP LOCKED` 协调；向量检索用 pgvector。
- **复核**：只有在多机部署或事件量级百万/天时才重新评估。

## ADR-0004 架构采用事件驱动

- **决策**：Collector → Event Bus → Scheduler → Memory/Brain → Sender。
- **理由**：多通道天然是事件源；可恢复、可重放、可观测。
- **后果**：所有模块围绕 Event 标准结构。
- **复核**：不预期变更。

## ADR-0005 内部 interface，对外 MCP

- **决策**：模块间用 Go interface 解耦；MCP 只用于对外暴露工具。
- **理由**：解耦靠接口不靠协议；MCP 有序列化/连接/调试成本。
- **后果**：MCP server 只在 P6 实现。
- **复核**：若需要跨语言模块（如 Python 插件），再评估内部 RPC。

## ADR-0006 OneBot 客户端自写，协议端用现成

- **决策**：协议端（NapCat/LLBot）不可控，永远用社区实现；客户端可自写。
- **理由**：协议端是逆向+风控重灾区；客户端只是 WS+JSON。
- **后果**：`pkg/onebot` 实现客户端；协议端可替换。
- **复核**：协议端稳定性变化时重新选型。

## ADR-0007 人格放 Phase 0，配回归测试

- **决策**：人格包化 + 回归集在 P0 落地。
- **理由**：产品核心是「同一条鱼」；没有回归就无法保证一致性。
- **后果**：任何 prompt/模型变更必须跑回归且通过率 ≥ 90%。
- **复核**：持续。

## ADR-0008 记忆采用双表 + 内联写入 + 异步提炼

- **决策**：`events`（事实层，必写）+ `memory_records`（提炼层，异步）。
- **理由**：现有 diary 只有提炼层，缺原始层；写入不能靠模型自觉。
- **后果**：发送器同步写事件，worker 异步提炼。
- **复核**：记忆量级或成本变化时调整提炼频率。

## ADR-0009 召回用三因子评分

- **决策**：`score = 来源权重 × 时间衰减 × 重要度 × (1+语义相似度)`。
- **理由**：现有 diary 只有时间范围+静态权重，没有衰减与相关性。
- **后果**：P0/P1 语义项为 0，P2 接 pgvector。
- **复核**：召回质量不达标时调参或换策略。

## ADR-0010 隐私隔离在查询层

- **决策**：私密/公开隔离在 SQL 层强制，不依赖 prompt。
- **理由**：模型可被诱导泄露；查询层是硬边界。
- **后果**：所有召回/查询接口带 channel ACL 参数。
- **复核**：持续。

## ADR-0011 Phase 0 三线顺序完成

- **决策**：弹幕 → 评论 → 私信，顺序做，不并行半成品。
- **理由**：先证伪架构，再复制适配器；同时开发三个通道会放大设计缺陷。
- **后果**：P0 退出标准只针对弹幕线 + 回归集 + 观测。
- **复核**：P0 完成后评估是否调整。

## ADR-0012 开发期本机跑，交付期 Docker

- **决策**：开发期不开 Docker Desktop；交付用 compose。
- **理由**：WSL2 VM 常驻占 1.5~2.5GB；本机直跑更快、更省。
- **后果**：提供 `scripts/dev.ps1` 一键启停。
- **复核**：换机器后重新评估。

## ADR-0013 成本与可观测前置到 Phase 0

- **决策**：预算/账本/心跳/日报在 P0 就有最小版。
- **理由**：静默失败比崩溃更可怕；成本失控是产品生死线。
- **后果**：P0 交付包含日志、日报、预算检查。
- **复核**：持续。

## ADR-0014 三通道 MVP 允许提前用

- **决策**：每个通道闭环后即可上线使用，不等全项目完成。
- **理由**：主人需要边开发边用。
- **后果**：通道可独立开关；未完成的通道默认关闭。
- **复核**：持续。

## ADR-0015 数据访问用 GORM 为主

- **决策**：GORM（pgx 驱动）作为默认数据访问方式；幂等插入、状态机迁移、`FOR UPDATE SKIP LOCKED` 用 `Raw`/`Exec` 手写 SQL。
- **理由**：与主人既有项目（lanmei-dream、ClaranCloudDisk）一致；CRUD 效率高；主人拍板。
- **后果**：
  - 幂等用 `clause.OnConflict{DoNothing: true}`
  - 状态迁移用条件更新 + `RowsAffected` 校验
  - 生产禁用 `AutoMigrate`，迁移用文件
- **复核**：出现 GORM 难以表达的查询/锁时，局部回退 Raw SQL，不改整体选型。

## ADR-0016 eino 按需引入（P0 不引入）

- **决策**：P0 自写 OpenAI 兼容客户端；eino 在出现「多步工具编排 / 复杂 agent 循环」时再引入；`Brain` 接口不暴露 eino 类型。
- **理由**：单轮对话用不上 Graph/ADK；eino 抽象重、版本迭代快（0.8/0.9）、依赖多；P0 引入是过度设计。
- **后果**：
  - `Brain` 接口保持自定义类型（`ContextInput`/`Reply`）
  - 自写客户端内置 `Provider` 抽象：OpenAI 兼容端点（DeepSeek/Ark/OpenRouter/Ollama 等）用同一实现，换模型/厂商只改 `llm.routing` 配置
  - 非兼容协议以后加适配器，`Brain` 接口不变
  - 如需引入 eino，最早在 P2（多模型切换）或 P6（工具循环），且只作为实现内部细节
- **复核**：P2/P6 前重新评估；若主人要求统一技术栈，可提前引入「薄 ChatModel 层」，不碰 Graph/ADK。
