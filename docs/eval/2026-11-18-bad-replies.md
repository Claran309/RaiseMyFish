# 蠢回复评测集（2026-11-18 起）

> 目的：把「鱼说蠢话」的真实案例固化成 test case，每次改 prompt/预算/模型后跑一遍对比。
> 只收录**真实发生**的弹幕（来自 events 表），不编造。

## 用法

```bash
# 1. 从库里导出最近 N 天「被认为蠢」的回复（人工挑，先手动）
# 2. 追加到下表
# 3. 改完 prompt 后，用同一批 case 让鱼重答（可以用脚本批量发合成事件）
# 4. 人工判分：通过 / 不通过
```

## 判分口径（三条，全过才算通过）

1. **不编造**：没有画面/记忆依据的内容不出现
2. **不重复**：不和最近 3 条自己的回复用同一个说法/梗
3. **不装傻**：被提到的人/事，能查到就别答「没听过」

## 真实案例（按时间）

| # | 时间 | 弹幕（节选） | 鱼的回答 | 问题 | 该怎么说 |
|---|---|---|---|---|---|
| 1 | 11-12 22:x | 「这里是不是又开始了」 | 「？？你倒是说清」 | 装傻/反问 | 先查最近弹幕 → 按上下文接 |
| 2 | 11-12 23:58 | 「叫你主人给你修修」 | 「修啥，鱼自己就能修」 | 嘴硬（事实是坏的） | 「好像是没 @ 上，鱼看看」 |
| 3 | 11-13 00:03 | 「又哪里种地了」 | 「种地怎么了，鱼就爱看这个」 | 画面认错（实际非种地） | 先看画面再答 |
| 4 | 11-13 23:50 | 「你知道奇迹鱼吗」 | 「奇迹鱼？没听过」 | 别名没召回 | 「奇迹鱼🐟啊，本鱼记得」 |
| 5 | 11-14 00:06 | 「鱼只认一个缸和让老板当女仆是有什么固定套路吗」 | 「老板不认，鱼只认一个缸」 | 公式化（130 次同梗） | 换说法/换梗 |
