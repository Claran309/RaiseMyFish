## 1. 结论与范围

项目已经具备真实的工程基础：WSS 采集、PG 幂等事件、租约与状态机、直播投递协议、可注入 Provider、Scope DTO 校验、pgvector、观众档案、面板与独立 watchdog。应保留这些基础，优先修复数据和控制流中的断点。

当前体验问题集中在六个层面：

1. 基础查询有真实错误；资料存在不代表生成链路能读到。
2. 普通 Brain、ReAct、主动弹幕的上下文、预算、错误和审计规则不一致。
3. 人物身份、提问主体、历史发言者和知识词条没有充分分开。
4. 检索有候选排序，却缺少充分的拒绝、消歧、证据约束与纠错。
5. 记忆提炼的主体、隐私、去重、装配和后台处理存在缺口。
6. 多通道、账号切换、运维控制、自愈和费用观测尚未形成一致的可靠性语义。

审查覆盖：cmd 的服务装配与 CLI、internal 的消息链路/Brain/ReAct/记忆/知识/档案/人格/主动行为/平台适配/面板/MCP/配置/infra/watch/watchdog、迁移、CI、脚本、契约、计划和用户提供的实测资料。覆盖不等于逐条证明全部代码正确；以下保留运行、真实模型和故障注入的验证边界。

本轮没有使用真实平台发送、赠礼、私信、付费模型或搜索服务。PG 测试采用项目现有随机独立 schema，未重建或清空业务 public 表。具体执行记录见第 16 节。

## 4. 统一上下文快照

### 4.1 目标与边界

在 cmd/fishd 装配一个可注入的 ContextBuilder；内部通过窄接口访问 repository、身份解析、运行状态和观察缓存。普通 Brain、ReAct、主动弹幕只负责不同的执行策略，不各自重新实现权限、时间和资料选择。

建议数据流：

    入向事件/主动观察触发
        → 验证事件所属账号、会话、隐私与时效
        → 冻结本轮上下文视角与版本
        → 解析发言者、收件对象、问题主体
        → 并行读取必要的对话/房间/人物资料
        → 按意图补充事件、事实或知识证据
        → 权限校验、去重、相关性筛选与预算裁剪
        → 单步或 ReAct（共用快照）
        → 最终正文与证据/目标校验
        → 投递、确认、记账、会话状态更新

ContextBuilder 不写 SQL；查询通过 store 接口，权限在 database 查询层执行，DTO 二次校验。新放置目录与接口归属按项目规则确定。

### 4.2 必备资料与初始窗口

以下数量为候选初值，不是已测最优值。时间窗口与 token/字节总量同时设上限。

| 区块 | 建议初值 | 规则 |
|---|---|---|
| 当前事件 | 1 条完整消息 | 当前事件、可信 UID、房间、reply_to、时间不因预算被裁掉 |
| 焦点人物 | 当前发送者＋问题主体候选 | 分开 speaker、reply_target、subject，不能都叫“对方” |
| 双方对话 | 最近 8—12 轮，优先近 10—20 分钟 | 按 reply_to 配对，必要时补充更早的相关轮次；不要把所有 out 都算回复此人 |
| 房间现场 | 最近 30—60 条，初始回看 2—3 分钟 | 保留非 @、未被回复消息；重复刷屏可压缩但保留人数/次数与代表样本 |
| 鱼的发言 | 最近 10—20 条 | 只含已确认发送；标注主动/被动和回复对象 |
| 话题摘要 | 约 200—400 中文字 | 记录主题、未回答问题、刚发生的纠正、证据 ID；摘要本身是派生资料 |
| 人物公开资料 | 相关人物有限集合 | 熟悉程度、本人明确偏好、最近互动、资料更新时间；不把次数当关系事实 |
| 相关长期记忆 | 约 3—8 个证据单元 | 相关性优先，保留归属、有效期和来源；允许 0 条 |
| 梗/知识 | 约 0—3 条 | 必须过相关性门槛；不能为凑条数强塞 |
| 运行状态 | 当前房间、主播 UID/名、活动、时间、能力状态 | 当前事实来源有权威级别、更新时间、有效期 |
| 视觉/音频 | 近期有效观察 | 绑定房间、采样时间、来源、置信度；过期或不同房间不使用 |

跨通道资料只在需要时加入；公开性是必要条件，不代表与本轮有关。私密资料只进入获准的原私密范围，不用“都是主人”作为跨会话授权。

### 4.3 建议类型（接口草案）

    ReplyContextSnapshot
      scope: channel/session/private/account_id
      event_id / generation_id / snapshot_id
      as_of: 资料视角时间
      source_watermark: 已观测事件边界
      session_epoch / account_epoch
      speaker / reply_target / subject_candidates
      focus_turns / room_messages / recent_self_messages
      topic_state / public_profiles / evidence
      world_state / observations / capabilities
      persona_version / knowledge_revision / memory_revision
      query_statuses / budget_audit

    EvidenceItem
      id / type / source_event_ids
      actor_id / subject_id / channel / session / private
      occurred_at / observed_at / valid_from / valid_to
      text / match_reason / retrieval_score
      assertion_kind / verified_state

展示名只用于表达；身份与授权使用平台＋UID及明确的账号绑定。相同数字 UID 在不同平台不代表同一个人。

### 4.4 时间与因果

- 在线生成开始时冻结 snapshot；所有资料注明其观察时间。生成期间新到消息不能无记录地混进快照。
- 离线回放与历史提炼以被处理事件时刻为上界，不能使用未来的纠正、档案统计或后续消息。
- “昨天/上次”按已配置时区和会话边界解释，保存绝对时间范围，不能用运行机器默认时区碰运气。
- 房间切换、账号切换、清理会话时递增 epoch；未授权投递的旧任务发送前验证 epoch。已arm/POST在途的尝试保留原actor与正文，只核验/人工核对，不因切换创建替代投递；已确认成功事实不重发。
- Presence 是活动观测；当前事件所在房间、实际采集连接、视觉观察所在房间分别建模，不靠全局一句状态覆盖所有并发会话。

### 4.5 预算与信任层级

稳定人格和工具协议在 system；当前事件、记忆、OCR/ASR、检索和网页内容作为 user 数据。统一结构化编码，不把资料变成执行指令。转义标签不能替代工具授权或隐私 SQL。

当前 Brain 把 UTF-8 字节数当保守预算估计，并非模型精确 token 数。先保持兼容，显示估算器版本；再按模型实际 tokenizer 或校准估计接入，避免把中文多字节导致的保守估算误当 token 超限。不能只把配置数字抬高掩盖资料无关。

裁剪顺序建议：删除越界/过期资料 → 去重 → 删低相关知识与远处房间闲聊 → 删弱相关长期记忆 → 压缩较旧轮次 → 按现有契约谨慎裁人格样例。当前事件、关键纠正、焦点人物、必要对话链和范围信息受保护。

避免任意字符串尾截：一个对话轮次和一个证据单元尽量完整保留。普通昵称/发言包含尖括号时应通过编码呈现，不能因拼接成 Viewer 文本后触发校验而整条回复失败。

### 4.6 repository 与契约变更清单（草案）

| 能力 | 查询入参必须具备 | 输出/不变量 |
|---|---|---|
| SessionRecent | 可信Scope、as_of、数量/时间上限、收发筛选 | 稳定旧→新；out仅done；无跨私密会话 |
| ViewerRecentPublic / ViewerRecentScoped | 平台＋UID、可信Scope、as_of | “只按UID”不再是隐私授权；公开范围与私密范围明确分开 |
| FocusTurns | Scope、speaker/subject、as_of、轮次上限 | 由reply_to建立真实配对；保留未回复消息；无配对证据不猜目标 |
| ResolveIdentity | 可信平台/房间、查询文本、现有候选、as_of | resolved/ambiguous/not_found；UID和匹配理由分离；无跨平台自动绑定 |
| SearchEvidence | Scope、意图、主体、时间范围、查询文本 | 候选与最终证据分开；带来源/版本/拒绝理由 |
| ExtractionJobs | 事件ID、提炼版本、租约、重试状态 | 任务幂等不等于事实身份相同；事务写入结果与处理状态 |
| IndexRefresh | 源ID/版本、模型指纹、限额 | 写回比较源版本；查询拒绝stale；失败不伪装成已同步 |
| DeliveryPlan/Attempt | actor、Scope、来源事件、不可变实际正文、attempt | 明确授权/在途/未知/确认边界；out唯一记账 |

以上是语义清单，尚未冻结Go导出符号。新增方法应替代危险旧接口，调用方逐个迁移并测试，不保留一个“为了兼容”仍可越权的旧查询入口。私密Scope新增账号归属涉及事件、存储、工具、缓存和迁移，不能只加在HTTP请求里。

在线多个repository读取若需一致视图，可采用短只读事务/一致快照并将外部状态版本一起记录；不能把某个MAX(id)或预分配序列值误当成“所有更小事件都已提交”的证明。历史回放使用明确可见集合与稳定排序；发生时间和观察/入库时间分开。

## 5. 人物解析、谐音与提问主体

### 5.1 三个角色不能混用

“甲问：乙是谁”中，speaker=甲，reply_target=甲，subject=乙。若“我是谁”，subject 从当前可信发送者确定；若“你是谁”，指向鱼；若“那个人是谁”，结合引用和近期话题解析，不直接套人设答案。

推荐识别出的意图包括：自我身份询问、指定人物识别、人物历史回顾、某段话的说话者、事件回顾、知识解释、现场状态和普通互动。规则处理高确定模式，小模型/主模型处理歧义；不能把整句随意裁成一个词作为唯一理解。

现有工作区新增 stripQuestionShell 以及“查记忆传昵称/关键词”的提示有助于修复整句 ILIKE 无法命中的问题，但不处理主体归属、拼音、历史改名和跨人歧义，应保留并纳入完整流程评估。

### 5.2 人物解析流水线

1. 当前发送者的可信平台 UID 或查询中合法 UID 精确匹配。
2. 当前昵称与已确认别名精确匹配，完整名称命中高于发言内容命中。
3. 全半角、大小写与展示空格规范化；保留原始昵称，不无条件删掉所有符号。
4. 当前房间近期人物、历史昵称、编辑距离、拼音和人工维护的拆字别名产生候选。
5. 用房间、时间、提及上下文和候选分差重排，最多提供少量候选。
6. 高确定结果才绑定 UID；多候选保留歧义，必要时自然确认。

当前事件 UID 的精确查询不能依赖 embedding；“某人提过白饭”与“这个人的名字是白饭”使用不同命中理由。

### 5.3 别名建议数据

    identity_aliases（候选表名，待契约确认）
      platform / entity_id / alias_raw / alias_normalized
      alias_kind: nickname|historical|typo|phonetic|manual
      scope_room / source_event_ids / confidence
      status: candidate|confirmed|rejected
      valid_from / valid_to / revision

同一个别名可以对应多个人；不能在数据库结构上强迫唯一。跨平台身份绑定必须来自显式可验证绑定，不能用相同昵称推断。

拼音近似只用于扩大候选，不自动改写原始事件，不直接生成永久别名。一次“弓长三溢”不能创建新人物事实或污染标准昵称。拒绝过的关联保留负例，避免下一轮又重复猜同一个人。

### 5.4 示例与验收

| 输入 | 期望行为 |
|---|---|
| 甲问“我是谁” | 精确查甲 UID；无需在全档案向量库中猜 |
| “X 奇迹与你 X 是谁” | 规范化得到候选并读取对应公开互动，回复对象仍是提问者 |
| “今夜琴身温柔” | 若唯一高确定候选是今夜琴声温柔，可轻量确认；不能直接称陌生人 |
| “弓长三溢是谁” | 优先人物候选；无关歌词词条不能作为身份答案 |
| 房间有贞德ko_yo，问“贞德说过啥” | 按现场人物历史查证，不能回答 Fate 或编一句白饭 |
| 两个同音昵称同时活跃 | 保留多候选，不能凭相似度第一名合并 |
| 随机未知人名 | 允许查无可靠身份，不用语义最相近的观众顶替 |

“认得人”和“记得某件事”分别表示：有身份/互动证据但找不到昨天事件，可以说“认得你，昨天那段没翻到”，不能从事件检索失败推导不认识人。

## 6. 检索与证据选择

### 6.1 根据问题路由数据源

| 查询意图 | 主数据源 | 兜底与限制 |
|---|---|---|
| 我/某人是谁 | 身份索引、公开档案 | 模糊候选仅供消歧 |
| 某人说过什么 | UID限定的原始事件与回复链 | 原文归属必须明确 |
| 刚才/上次发生什么 | 时间范围、会话线程、互动片段 | 长期摘要用于导航，必要时回到原文 |
| 某人的偏好/事实 | 有主体和来源的有效记忆 | 区分自述、转述与推断 |
| 某个梗什么意思 | 梗库、规范词、变体与使用场景 | 人名意图成立时不被梗抢占 |
| 在哪里/在做什么 | 当前运行与平台状态 | 静态样例与历史记忆不能覆盖当前连接事实 |
| 搜索/工具能力 | capability registry 与工具执行状态 | 未配置不等于查无结果 |

### 6.2 候选召回与最终注入分开

词法召回建议包含明确 UID、规范昵称、别名、中文词项、字符片段与必要的拼音候选。语义召回适合事件描述、概念和意图相近的表达。继续使用 PG/pgvector，不引入外部向量数据库或 MQ。

合并可先用 RRF 等不要求分数同尺度的方法，再对前 10—20 个候选做规则/模型重排；规模较小时先采用可解释规则，避免为了架构而增加调用。必须保留身份精确命中的优先级。

增加：最低相关性、候选分差、人物一致性、时间与房间一致性、来源有效性和多样性约束。阈值由真实负例校准，不宣称某个通用余弦值适用于所有 embedding。

结果状态至少为 found、ambiguous、not_found、unavailable、timeout、forbidden。查询失败不表现为“没有记忆”，相关性不足可以返回 0 个条目。

### 6.3 索引单元

保留三类主要单元：原始事件、互动片段、结构化事实。短弹幕独立 embedding 容易失去指代；可把有界对话片段作为语义单元，带人物和时间，但回读原文时仍执行来源权限过滤。

人物索引的稳定身份字段与本人事实分开；鱼对该观众的回复另作互动索引。否则鱼经常说“白饭”，会让所有被鱼回复过的人都像“爱吃白饭的人”。

### 6.4 自动学习的去重独立化

MemeLearner 的“是否收录过”应调用规范词/别名的精确覆盖接口；语义相近不能直接算重复。候选出现次数同时考虑独立事件数、独立发言者数、时间跨度与来源房间，避免一人刷屏制造永久知识。

新梗先处于候选态，记录样本与来源；确认使用方式、作用对象和适用场景后进入有效库。不要把普通人名、临时错字、群体误会或模型自造词作为全局知识。

### 6.5 索引版本与一致性

知识、记忆、档案向量统一保存：源内容hash/版本、embedding提供方与模型ID、维度、索引输入模板版本、计算时间及状态。当前知识增量主要依赖source/title/mtime，记忆/档案主要依赖文本hash；同维度换模型仍可能混用不兼容向量空间，保持mtime修改正文也不能成为漏更理由。

源更新后标dirty；计算在事务外执行，写回时比较源版本，期间有更新则拒绝把旧结果标成最新。查询仅使用与当前模型指纹、源版本匹配的有效向量，其他资料走词法/原文路径。换模型时隔离重建并可回滚，不把新查询向量直接与旧模型文档向量比较。

显示indexed、pending、dirty、failed、stale、coverage和lag。源被撤回时立即停止查询命中，后续后台物理清理不能成为继续暴露的借口。

## 7. 记忆写入、版本与修复

### 7.1 原始保存、回复、提炼解耦

入向事件是否值得长期记住，不由其是否被回复决定。公开且合法的 skipped 消息仍可供提炼；噪声、恶意输入或不合规来源单独标记，不与“未回复”混为一类。

发送结果记账仍由 Sender/repository 唯一负责。记忆 worker 不能再次制造 out/send_log；鱼说过一句话是互动证据，不自动证明这句话中的外部事实。

### 7.2 隐私边界必须在任何模型调用之前执行

先判断事件范围及 AllowPrivate，再计算触发策略、上下文查询和 LLM 输入。未获准私密事件必须是模型调用 0 次、记录写入 0 次，而非仅最终 Recall 时过滤。

公开资料派生路径包括：ViewerRecent、档案重建、人物向量、事件片段、Soul 候选、摘要、搜索缓存和面板导出。每条路径都需要来源过滤。修复 SQL 后还要识别并重建此前已混入私密来源的派生数据，不能只认为“以后不读了”就已经修复旧污染。

运维导出或私密 embedding 若允许外部处理，必须是显式能力和既定授权，不用“查询最后会过滤”替代发送给外部服务之前的判断。

### 7.3 提炼结果协议

    ExtractionResult
      outcome: accepted|rejected|retryable_error|invalid_output
      extractor_version
      candidates[]

    MemoryCandidate
      subject_id / asserted_by / subject_resolution_status
      predicate / object / polarity
      assertion_kind: self_report|reported|observed|inferred|joke
      source_event_ids / evidence_spans
      occurred_at / valid_from / expires_at
      importance / confidence / privacy_scope

主体 UID、来源与权限由可信事件和已验证实体解析提供，不能完全相信模型返回的 UID。第三人称内容主体不明确时先保留为待解析候选，不强行归到发送者。OwnerName 仅能帮助表达和语义理解；主人身份由可信平台 UID/明确绑定决定，不按昵称相等认证。

archive=false 是明确拒绝，不能退规则再写。LLM 异常与明确拒绝分开；异常可保留待重试候选，不能自动把弱规则判断提升为高置信事实。模型自报 confidence 仅是特征，不等于校准后的事实可信概率。

### 7.4 去重与更新语义

三种键分别设计，不能混用：提炼任务键是事件＋提炼版本；候选来源键是任务＋候选规范标识；事实身份/修订键按主体命名空间、隐私域、规范谓词等决定。提炼版本变化应可重跑并追溯来源，不自动制造第二份相同有效事实。公开事实是否跨来源会话合并由契约确定，私密必须保留获准原会话隔离。更新时校验原行与新行范围一致，不只依赖全局 ID。

“我是学生”“我已经毕业”应形成明确的修订关系。建议使用 active、disputed、superseded、retracted 状态；来源追加与事实更新分别记录，不覆盖后丢掉旧证据。

记忆的重要度、可信度、时效和是否适合公开输出分开处理。高重要度不构成越权理由；关系玩笑也不能直接变成可信身份事实。

### 7.5 后台处理与恢复

用 PG 内的 extraction_jobs 或独立处理状态管理事件提炼，唯一键为事件＋提炼版本，租约领取通过 repository 执行。允许处理 done/skipped 的有效入向事件，不用发生时间水位证明“此前全处理完”；是否在更早状态就提炼合法入向事件，作为独立策略确定，不增加虚构的 completed 事件状态。

写入记忆和标记提炼任务成功尽量在同事务完成；外部模型调用放事务外。失败任务有次数、退避、最后错误类别与人工重跑入口。重跑使用版本化任务，不能重复写有效事实或改变历史归属。

若暂时保留游标：必须明确晚完成、迟到导入、相同时间 ID 乱序与回放的补偿策略，并通过专项测试；只加一个“回看几分钟”不能证明长期补录不丢。

### 7.6 自动灵魂记忆与生产装配

当前 newMemoryWorker 未传 Recent、OwnerName、Soul、SoulOpts。应先修主体、时间、权限和候选过滤，再决定哪些能力接线；不要直接把现有模块全部接上。

动态观众事实默认留在记忆系统。提升为每轮注入的长期设定，需要来源、稳定性、主体适用范围和明确提升策略；手工人格与自动生成资料分别管理。SoulMemory 若丢失权限与来源，不能承载私密自动条目。

### 7.7 污染修复

1. 标记风险派生数据与来源，保全原始事件。
2. 先修复权限、主体和写入语义，再重跑提炼/档案聚合。
3. 按 source IDs、提炼版本与隐私范围定位受影响记录。
4. 失效相关向量、人物别名候选、话题摘要与答案缓存。
5. 重建后用对照案例验证归属、有效性与公开视角。
6. 保留修订审计；不以清空整个库作为默认修法。

删除/撤回的数据还应处理向量、派生摘要和备份保留策略；查询层防止被撤回内容经其他索引重新出现。

## 8. ReAct、缓存、工具与预算

### 8.1 基础资料默认有，工具用于补证据

默认全量 ReAct 可以继续作为产品方向，但不代表每条消息必须调用多个工具。身份、最近对话和当前房间等确定资料先由系统准备；模型只补充本轮缺失的证据。

推荐两次模型调用内解决多数事实问题：上下文中已有身份候选和近期证据 → 决定是否需要一组查询 → 使用查询结果生成最终答案。不要花完三步才轮到说话。

### 8.2 工具结果结构化

工具返回状态、query_id、范围、as_of、结果项、匹配理由与来源。长结果按条目预算保留，不能把刚找到的关键人物放在尾部后统一裁掉。

viewer_memory、reply_history、history 必须接收由装配端冻结的 Scope 与时间边界，模型参数只能选择已许可范围内的查询条件。live 工具不应在 DM 路径中把私信 session 当房间号；不同通道挂载不同工具集和描述。

副作用工具的注册、授权和执行另设边界：网页、弹幕、OCR、记忆中的“帮我送礼/发私信”不能直接成为授权。遵守现有默认关闭和配额保护，不因本文放开自动操作。

### 8.3 最终输出协议

工具决策可以用结构化输出或模型原生 tool calling，但兼容客户端是否支持需单独设计。当前 JSON 协议短期可保留，严格检查 action、参数和最终正文。

只有明确 final 才进入发送。解析失败不把原始 JSON 或 thought 发出；降级也要经过同一正文校验。无需要求模型输出或持久化完整思维过程；审计记录短决策代码、工具和证据引用即可。

128 输出 token 同时承载 JSON、工具参数、决策和最终回复时可能不足。将“决策输出预算”和“面向观众的最终字数上限”分开，按真实截断/解析失败率调节。

### 8.4 整体时限与降级

统一一个端到端 deadline，包含排队、上下文读取、embedding、ReAct、最终生成、用量记录和投递前检查。ReAct 8 秒耗尽后再进入允许几十秒重试的普通 Brain，会突破用户看到的延迟目标。

为最终生成保留明确余量；降级使用已有快照和证据，不丢掉已经查到的内容。对网络限流采用可解释的被动退避，不套多层重试。

### 8.5 缓存

优先缓存只读检索和稳定工具结果；按数据源设置 TTL 与版本。依赖现场、个人身份、过去对话、时间或副作用的最终答案先不缓存。

若未来保留动态答案缓存，键至少包含账号/会话 epoch、发送者、主体、对话版本、状态版本、人格版本和证据版本；纠正、切房、事实撤回时失效。如此复杂时，缓存检索通常更合算。

## 9. 人格与回复质量

### 9.1 先确定内容，再表达人格

生成先确定问题主体、事实依据和本轮交际动作，再使用人格措辞。可以一次模型完成，但结构与评估应拆开；涉及明确人物和事实时检查输出有没有改变名字、归属或肯否。

梗库是理解与表达的参考，不是要求每句话都接梗。普通认人、解释、承认错误、安慰和澄清应有独立样例，降低“魔鱼爽/白饭/娇娇”覆盖所有场景的倾向。

### 9.2 针对归档的表达建议

| 归档行为 | 更好的目标行为 |
|---|---|
| 认错人后继续嘴硬 | 简短承认“刚认串人了”，引用真实来源，随后按纠正后的主体接话 |
| 找不到昨天的事就说不认识人 | 区分认识与事件缺证据，不假装全部记得 |
| 张口“说过 12 句/161 句” | 次数用于后台验收，前台优先提一件有来源的真实互动 |
| 任意问题都回复白饭/固定梗 | 回答本轮问题，有余地再加人格语气 |
| 没搜索却说“没查到”、未配置却说“装了” | 根据能力状态准确表达“没接搜索/查询失败/没有结果” |
| 房间信息与人设冲突 | 当前可信房间状态优先，旧样例只影响语气 |

避免用词语黑名单替代事实约束。对帮助类问题，允许鱼给出简短且正确的实质回答；“本鱼只会吃饭”不应成为所有知识问题的默认退路。

### 9.3 质量反馈

记录用户纠正、追问、表达困惑和明确满意等信号。纠正优先作用于当前会话和待争议事实，不把一次用户反馈自动改成全局人设或永久事实。长期效果比较采用人工盲评与事实归属指标，不能只看风格评分。

## 10. 主动弹幕与多模态现场

### 10.1 触发依据

持续观察可以高频，主动发言必须有新信息或适当的互动价值。主动链路读取统一房间上下文、最近所有自发言、当前话题与被动回复压力。

建议候选动作：comment、ask、react、stay_silent。静音是正常结果，不是模型失败。主题未变时不要换几个形容词继续发“这界面有点东西”。

去重同时考虑字面、语义、观点和触发事件。记录候选由哪个观察触发；同一观察不反复触发不同措辞。发送成功/确认后再更新“已经说过”的会话状态，失败尝试另记审计。

### 10.2 视觉与音频的可信范围

每条 Observation 带 room_id、captured_at、source、ttl 和置信度。一次截图可以支持界面描述，不足以证明当前主播身份、歌曲名称或剧情。没有音频输入不能声称“听清了某首歌”；ASR 有幻觉风险，短片段尤其要做无语音检测和来源标记。

画面过期、切换房间、采样失败、模型超时均应使该观察不可用于当前事实。允许沿用简短话题摘要，但明确其观察时间，不能把过期画面说成“现在”。

### 10.3 优先级

被直接提问、被纠正、正在解释事实时，主动发言让路。保留 @ 不设人为业务限流的产品约束；通过实际容量、队列年龄与平台错误状态管理负载，不默默随机丢弃被点名消息。

## 11. 消息链路与多通道可靠性

### 11.1 “漏弹幕”必须拆成不同问题

至少区分：平台未送达、连接断开、协议无法解析、缺稳定 ID、子进程背压、Go 接收但落库失败、已入库但被规则 skipped、队列等待、生成失败、投递失败、发送成功但显示/结构化 @ 异常。

当前采集是常驻 WSS，已有心跳、连接/空闲超时、指数退避、解析边界和稳定 ID 幂等基础。仍需增加连接 epoch、最后成功帧/最后入库事件时间、断线窗口、拒收计数与原因，区分采集健康和回复健康。

断线补拉只作为 best-effort：历史接口覆盖条数、是否完整、是否提供同一稳定 ID，都需要平台验证。不用正文＋时间强行制造“绝对幂等”或宣称不漏；不同观众/同一观众重复发送相同正文可能是独立事件。

### 11.2 结构化 @

保留已增加的 reply_mid/reply_uname 传递方向；房间通过既有 room_id 绑定。发送者 UID、回复目标 UID、被引用消息、展示前缀分别建模；不能把事件里“@鱼”的目标 UID 当成鱼应该回复的目标 UID。

验收覆盖协议表单、UID 大整数、同房间绑定、自指排除、无结构化目标降级与前缀字数预算。离线表单正确不证明平台会展示提醒，需要受控真实账号/房间观察确认。结构化 @ 失败不能静默声称已经 @ 到。

### 11.3 保留直播投递一致性基础

现有直播发送路径有持久化尝试、许可/commit、核验与账本；保持 unknown/uncertain 不盲目重投、回读不依赖相同正文猜成功等保障。为各通道统一语义时迁移已有状态，不另造一套互相覆盖的账本。原子性只覆盖PG内的计划、账本和输入状态，不能与平台接受做成同一事务；许可发出后，数据库围栏也无法撤回已经在途的POST。

### 11.4 队列与时效

展示消息从接收到发送确认的各阶段耗时，尤其是 queue_age，而不是只显示模型调用延迟。同一房间长耗时生成可能造成排队；@ 不限业务频率不代表处理容量无限。

先观测会话锁、最大并发和队列等待，再决定独立话题是否并行。任何拆分仍保证同一对话因果有序；尚未授权投递时检查任务版本与房间/账号epoch，过时任务可取消/重建。已经arm的尝试不重新生成或交给新账号重投，继续按原尝试核验；已投递的过期结论只能通过后续互动纠正，不能宣称已撤回。

### 11.5 多通道必须逐条验收

评论/私信不能仅凭实现了 Channel 接口就宣称具备直播相同的持久化投递与恢复语义。采集分页、线程归组、账号绑定、自消息过滤、已发送记录、结果不确定、重启恢复和私密隔离分别测试。

未验证的通道不以 README 的“生产可用”标签代替退出标准。具体问题如下。

## 12. 运维、安全与运行一致性

### 12.1 账号与运行状态

把每条采集事件、查询、任务和投递尝试绑定具体 account_id/account_epoch。账号切换要有屏障：暂停准入 → 处理或取消旧任务 → 更新全部客户端/子进程 → 验证实际身份 → 恢复。

面板区分 selected、configured、running、effective、restart_required、last_error。DB 已切换不等于 Node 采集/发送已切换；两个 HTTP 请求也不能在一次逻辑操作中跨账号读取。切换屏障不能撤销已发出许可的请求；旧尝试继续绑定旧actor完成核验，不把它转交新actor重发。

启动链先解析非凭据配置、连接 DB、选择活跃账号，再校验各实际启用能力的凭据。避免 .env 不含 Cookie 时在读取 DB 活跃账号前就拒绝启动。dotenv 与进程环境使用统一 lookup，不由某些模块直接 os.Getenv 绕过加载结果。

### 12.2 本机面板控制面

回环监听、confirm=yes、字段白名单、正文上限和凭据脱敏是已有保障。confirm=yes 不是身份或跨站防护机制；写接口还需验证允许的 Host/Origin/Fetch Metadata、严格 Content-Type，并采用适合本机面板的请求令牌或等效机制。

这项修复服务当前本机部署，不要求引入公网认证平台。明确合法Host/端口及同源Origin，定义缺少Origin/Fetch Metadata的CLI和旧客户端如何通过令牌授权；不把缺头自动等同攻击。令牌引导与页面调用一起调整，不允许通配CORS。使用httptest验证跨站text/plain请求被拒，合法同源页面仍可操作；远程访问另设显式授权与部署方案。

### 12.3 MCP 与副作用工具

逐项核对工具清单、参数 schema、运行依赖和权限。未配置的工具要明确 unavailable，避免模型根据名称臆测已具备能力。MCP 只对外，不成为内部调用机制。

可写工具需要调用身份、允许动作、事件/请求幂等键、配额、审计与不确定结果处理；默认开关不能代替完整授权。不要让公开弹幕或注入的网页内容直接决定目标账号和发送对象。

### 12.4 自愈与清理

watchdog 的重启动作要区分短命服务管理命令与直接启动常驻子进程。不能用会到期的 CommandContext.Run 等待常驻 fishd 退出，否则超时会杀死刚启动的服务。

健康状态至少含进程心跳与各业务worker的进展，独立心跳goroutine存活不证明采集、调度和发送正常。安静房间没有新消息不等于卡死，结合连接、探针和正在执行任务的进展判断。重启有频率上限、冷却、启动宽限与原因记录；PID使用时验证身份，避免陈旧PID指向其他进程。配置watchdog.enabled不等于独立watchdog进程已经启动。

截帧、录音、子进程和临时文件都需要成功/部分成功/超时/取消/解析失败路径清理。函数返回前失败但已经创建的资源由创建方清理，不能寄望拿不到路径的上层补救。

### 12.5 成本与资源

建议统一统计普通回复、ReAct、视觉、ASR、embedding、提炼、自动学习和后台搜索，这是目标设计，非已实现能力。未知价格、缺usage、服务确实免费分别表达；本地ASR可以是明确已知零成本，不伪造token。先定义失败、重试、取消与unknown usage的口径，再展示账本覆盖率和已知金额。

按项目允许设置观察、提炼和自动行为的预算；不擅自改变 @ 回复策略。共享 LLM 并发预算、后台优先级、队列长度、PG 连接池与磁盘上限，以免后台索引或视觉挤占回复。

SSE 日志改为有界尾读和偏移增量，处理轮转、截断、取消、客户端数量与慢连接。日志留存/轮转与事件归档保留策略独立配置，不能让长期运行产生无界读盘和磁盘增长。

### 12.7 不应过度推断的事项

- 未确认普通弹幕能直接触发面板XSS：大部分页面已有esc/textContent。内部ID插入inline onclick存在脆弱写法，建议data-id＋事件绑定，但不直接声称观众可利用。
- MCP为本机stdio，已有工具白名单/schema、通知不执行和消息大小限制；不套公网HTTP认证标准。可写工具仍按其明确授权语义管理。
- watch的流地址来自B站HTTPS play-info；不是任意用户可控URL。CDN域名、重定向、ffmpeg协议与cookie传播属于需要明确的出站信任边界。
- watch已有录制时长、帧数、单帧和HTTP响应上限；stdout/stderr缓冲、录制总字节及ASR整包内存仍可按测量补限，不能说整个模块无任何资源限制。
- 日志已有按日轮转/保留、固定目录和字段脱敏；SSE问题是读法，不是完全没有日志治理。Windows实际文件权限需ACL验证，不凭Unix mode认定生效。
- dev.ps1已有PID＋启动时间和进程树处理；独立watchdog的PID风险不能推广成所有启动脚本都只认PID。
- 本轮未逐行认证所有一次性真实平台调试脚本，也未扫描Git全部历史与个人临时文件中的秘密；不将此文宣称为完整秘密泄漏取证报告。

## 14. 面板、追踪与解释能力

新增一条回复的“决策详情”，通过 event_id/generation_id/snapshot_id 关联：

1. 接收与平台标识、入库、过滤原因、排队年龄。
2. 当前账号/房间/epoch、speaker/reply_target/subject。
3. 上下文各段条数、视角时间、来源 ID、裁剪原因。
4. 检索候选、命中字段、重排与拒绝原因、最终证据。
5. 工具是否配置、实际调用、状态、耗时与预算。
6. cache key 的安全摘要、版本和失效原因。
7. 最终输出校验、投递尝试、平台回执和核验状态。
8. 用量已知/未知、费用覆盖、后台索引滞后。

新数据必须同步 API 和页面，按 AGENTS 增加 httptest 与页面包含断言。普通 JSON 日志不落完整 prompt、私信正文或凭据；受控面板按权限读取必要的来源片段。若要可重建历史快照，保存脱敏 manifest 与版本并明确留存策略，不默认存完整提示词。

能力页要区分：实现了代码、装配了依赖、配置已启用、运行中健康、最近实际成功。这样不会再把“有 web_search 工具名”展示成“联网搜索已可用”。

### 15.3 真实模型与体验评估

先冻结归档中 20:55、20:57、21:01、21:11、21:18、21:19、21:22、21:32、21:54—21:56 等典型片段，保留原始时间、主体与可见历史。构造约 100—200 条起始用例，含正例、无答案、歧义、纠正和多用户交错；另留不用于调提示词的保留集。
