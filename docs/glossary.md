# 术语表

> 项目内黑话统一定义，防止 agent 理解漂移。新增术语请补这里。

| 术语 | 定义 |
|---|---|
| **通道（Channel）** | 一个消息平台入口：live / comment / dm / qq |
| **事件（Event）** | 标准化消息单元，带幂等键与状态 |
| **幂等键** | 事件唯一标识，重复投递只处理一次 |
| **事件总线（Bus）** | 事件的幂等入库与消费，P0 用 PG + 进程内通知 |
| **调度器（Scheduler）** | 决定「回不回、何时回、用谁拼」，产出 Task |
| **任务（Task）** | 调度器产出的待处理单元，指向一个事件 |
| **大脑（Brain）** | 把「事件 + 记忆 + 人格」变成回复的执行器，可插拔 |
| **人格包（Persona Pack）** | soul / rules / samples / context 的版本化数据包 |
| **记忆记录（Memory Record）** | 从事件提炼出的长期记忆 |
| **事实层** | `events` 表，全量原始事件，必写 |
| **共享状态（Shared State）** | 跨通道可见的当前事实（直播中/余额/未回私信） |
| **召回（Recall）** | 按三因子评分选取记忆注入上下文 |
| **版本化（Versioning）** | 同一事实变化时旧记录失效、新记录生效 |
| **死信（DLQ）** | 重试耗尽的失败任务/事件 |
| **静默失败** | 进程活着但不在回消息，比崩溃更难发现 |
| **冷却（Cooldown）** | 同会话回复后的静默期 |
| **令牌桶（Token Bucket）** | 按速率发放发送许可的限流器 |
| **投递-确认** | 发送后必须核验，失败进重试 |
| **MCP** | Model Context Protocol，对外暴露工具的协议 |
| **Phase** | 开发阶段，见 `plans/` |
| **ADR** | 架构决策记录，见 `docs/14-decisions.md` |
| **MVP 闭环** | 单通道从采集到发送到观测全链路可用 |
