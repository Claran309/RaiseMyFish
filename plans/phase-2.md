# Phase 2 · 记忆正式化

> 目标：把 P0 的「事件必写 + 简单提炼」升级为完整记忆系统：
> 价值识别、三因子召回、事实版本化、归档压缩、隐私过滤。

## 依赖

Phase 0、Phase 1（事件量与多通道数据）。

## 任务清单

### 2.1 提炼 worker
- [ ] 扫描新 done 事件（游标/水位）
- [ ] 价值识别：规则优先（主人/承诺/首次），LLM 兜底
- [ ] 写入 `memory_records`（importance/confidence/private/valid_from）
- [ ] 批量与限流（避免烧 token）

### 2.2 实体与关系
- [ ] `memory_entities`（人/频道/游戏/话题）
- [ ] `memory_relations`（喜欢/讨厌/认识/承诺）
- [ ] 提炼时关联实体

### 2.3 召回
- [ ] 三因子评分：来源权重 × 时间衰减 × 重要度
- [ ] 预算分层（会话滑窗 / 共享状态 / 24h 重要 / 长期）
- [ ] 按通道 ACL 过滤 private（SQL 层）
- [ ] 召回结果带 confidence 标签

### 2.4 事实版本化
- [ ] 同 `(entity, key)` 写入 → 旧记录 `valid_to`、新记录生效
- [ ] 查询默认只返回当前有效
- [ ] 历史可查（`fishctl memory history`）

### 2.5 归档与压缩
- [ ] 衰减阈值 → `archived=true`
- [ ] 同话题低价值记录 → LLM 合并 summary
- [ ] events 表 90 天归档

### 2.6 语义召回（可选）
- [ ] pgvector 扩展 + `memory_embeddings`
- [ ] 召回时 `(1+sim)` 因子
- [ ] 先做开关，默认关

### 2.7 迁移
- [ ] `~/.dsh/diary/memory/` → PG 导入器
- [ ] 保留 `global-memory/1` Markdown 导出

### 2.8 测试
- [ ] 写入路径（高/中/低价值）
- [ ] 版本化测试
- [ ] 召回排序与预算测试
- [ ] 隐私隔离测试
- [ ] 重启后补提炼

## 退出标准

1. 重启后未提炼事件能自动补上
2. 同一事实变化后，召回只返回新值（历史可查）
3. 公开通道召回不到 private 记忆（单测 + 抽查）
4. 召回预算不超上限，人设不被挤掉
5. 迁移 diary 数据后，召回结果与人工抽查一致

## 风险

| 风险 | 应对 |
|---|---|
| 提炼成本高 | 规则优先、批量、便宜模型 |
| 召回污染（错误记忆进上下文） | importance/confidence 门槛 + 人工抽查 |
| 向量召回质量差 | 默认关闭，评估后再开 |
