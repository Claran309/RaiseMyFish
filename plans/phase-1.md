# Phase 1 · 评论 + 私信通道

> 目标：把弹幕线的架构复制到评论与私信，验证「一套核心、多通道适配」成立。
> 顺序：评论 → 私信（不并行）。

## 依赖

Phase 0（弹幕线闭环、事件总线、调度器、Brain、Sender 框架）。

## 任务清单

### 1.1 评论通道
- [ ] Collector：收件箱轮询（回复我的 / @我的 / 动态评论）
- [ ] 幂等键 `comment:{oid}:{rpid}`；记录 root/parent
- [ ] Sender：顶层 / 楼中楼（`--root`）
- [ ] 核验：回读 state == 0；state 17 不重发；12002 跳过
- [ ] 长度上限 200 字
- [ ] 「视频 @」场景：先获取视频内容再回（可先只读标题/摘要）

### 1.2 私信通道
- [ ] Collector：等回话会话轮询（复用 dm-await 逻辑）
- [ ] 幂等键 `dm:{uid}:{msg_id}`；主人白名单
- [ ] Sender：文本 ≤500 字；回读确认
- [ ] `private=true` 强制（查询层隔离）

### 1.3 通道开关与配置
- [ ] `channels.comment.enabled` / `channels.dm.enabled`
- [ ] 每通道独立配额/冷却

### 1.4 跨通道一致性
- [ ] 共享状态：三通道可读到彼此最近事件（公开通道过滤私信）
- [ ] 人格 context.md 按通道选口径

### 1.5 测试
- [ ] 两通道 mock 测试（成功/失败/核验失败）
- [ ] 私信不外泄测试
- [ ] 三通道并发测试

## 退出标准

1. 三通道同时运行一天：无重复回复、无漏回（抽样验证）
2. 私信内容不出现在公开通道上下文（单测 + 日志抽查）
3. 三通道语气一致（回归集扩大到含评论/私信场景）
4. 任一通道关闭不影响其他通道

## 风险

| 风险 | 应对 |
|---|---|
| 评论状态核验复杂 | 先只做视频评论，动态评论后置 |
| 私信白名单误判 | 非白名单进待审，不自动回 |
| 三通道成本翻倍 | 配额按通道分别设 |
