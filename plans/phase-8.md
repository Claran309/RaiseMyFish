# Phase 8 · 开播（虚拟形象 + 互动）

> 目标：让鱼能开播，实时渲染人物形象并回弹幕。
> 这是独立子系统（渲染管线），不是纯后端。

## 依赖

Phase 5（面板）、Phase 6（工具能力）。

## 架构

```
┌─────────────────────────────────────────────┐
│ 渲染管线（独立进程/工具）                    │
│  Live2D / 3D 形象 + 口型同步 + 表情          │
│  OBS 采集推流                               │
└──────────────▲──────────────────────────────┘
               │ 表情/动作/口型指令
┌──────────────┴──────────────────────────────┐
│ fishd（后端）                                │
│  弹幕 → brain → 回复 + 表情指令              │
│  TTS 语音（可选）                            │
└─────────────────────────────────────────────┘
```

## 任务清单

### 8.1 形象与渲染
- [ ] 选型：Live2D（推荐，成本低）或 3D
- [ ] 形象资源（现有 `~/.dsh/tts/you/sprites/` 可作为参考）
- [ ] 口型同步：TTS 音素 → 嘴型参数
- [ ] 表情/动作指令接口

### 8.2 TTS
- [ ] 音色选择
- [ ] 与人格语气匹配
- [ ] 延迟控制

### 8.3 推流
- [ ] OBS 场景配置
- [ ] 推流稳定性
- [ ] 画面安全区（弹幕/礼物叠加）

### 8.4 弹幕互动
- [ ] 开播时弹幕回复
- [ ] 表情/动作响应（被夸→害羞，被调侃→炸毛）
- [ ] 礼物感谢

### 8.5 开播管理
- [ ] 开播/下播流程
- [ ] 直播状态接入面板
- [ ] 异常处理（断流、画面卡死）

## 退出标准

1. 能稳定开播 1 小时，画面/口型/弹幕互动正常
2. 断流后能自动恢复或告警
3. 开播状态在面板可见
4. 不依赖人工盯守

## 风险

| 风险 | 应对 |
|---|---|
| 渲染管线复杂且与后端不同技术栈 | 独立进程，接口隔离 |
| 平台开播规则 | 先读平台对虚拟主播的规定 |
| 口型/表情延迟 | 本地 TTS + 预生成 |
| 成本（TTS/渲染） | 本地模型优先 |

## 不做

- 实时 3D 高精度（成本过高）
- 多人联动
