> 目标：让鱼能玩星露谷物语。走 SMAPI mod + 决策循环，不做内存破解。

## 依赖

Phase 6（MCP 工具层）。

## 架构

```
SMAPI mod（C#，游戏进程内）
  ├─ 状态 API：玩家位置/背包/金钱/时间/天气/作物
  └─ 动作 API：移动/交互/种地/浇水/钓鱼
        ↕ HTTP/WebSocket（本地）
MCP server（包装成 tools）
        ↕
决策循环（brain/agent）
```

## 任务清单

### 7.1 SMAPI mod
- [ ] 环境：正版游戏 + SMAPI
- [ ] 最小 mod：暴露 `GET /state`（只读）
- [ ] 动作接口：`POST /action`（移动/交互）
- [ ] 安全：只监听本地；动作白名单
- [ ] 日志与错误处理

### 7.2 MCP 包装
- [ ] `game_get_state` / `game_action`
- [ ] 动作参数 schema
- [ ] 限频（防手抖循环）

### 7.3 决策循环
- [ ] 感知（读状态）→ 决策（LLM）→ 执行（动作）→ 观察（结果）
- [ ] 步数上限 / 超时 / 中断
- [ ] 状态机（种地/钓鱼/探索）
- [ ] 失败恢复（卡住 → 重新决策）

### 7.4 安全与边界
- [ ] 不读内存、不注入
- [ ] 不修改存档关键数据（除非明确需求）
- [ ] 游戏崩溃恢复

## 退出标准

1. 能读游戏状态并执行基础动作（移动/种地）
2. 完成一个完整任务（如种一季作物）不掉线
3. 决策循环有步数上限，不会无限循环
4. 不影响游戏正常存档

## 风险

| 风险 | 应对 |
|---|---|
| SMAPI 版本更新适配 | 锁定游戏/SMAPI 版本，mod 单独维护 |
| 动作延迟/卡住 | 超时 + 重试 + 重新决策 |
| 决策成本高 | 决策频率限制，规则兜底 |
| 游戏窗口遮挡 | 建议全屏/固定窗口，截图稳定 |

## 不做

- 实时动作游戏（MCP 延迟不够）
- 内存读写/外挂
