# Change Note: 带租约的事件总线与崩溃恢复

## 1. What Changed

本次新增 Phase 0.3 事件总线：Publish 幂等写库，Notify 发送合并通知，ClaimPending 原子领取到期事件，Mark/Defer/Renew 检查持有权，Recover 恢复过期工作。契约先升级为 P0-EVENT-2，随后实现和验证。

queued 现在表示“已被领取”，由 stage 区分首次调度、已有任务的生成、只允许核验的补偿。Task 写入和生成阶段切换放在一个事务内。新增 0002 迁移保存租约，不改已应用的 0001 和 seed。

## 2. Why This Change Was Needed

旧文档一方面要求 Claim 把 pending 改成 queued，另一方面又要求调度器只处理 pending。它也没有说明重启后谁有权更新事件、怎样判定超时，或怎样区分生成重试和发送补偿。

只加一个内存队列不能解决这些问题：进程退出后内存会消失，旧 worker 也可能在新 worker 接手后才返回。现在 PostgreSQL 保存状态和租约，进程内 channel 只用于减少等待。恢复依据数据库到期时间，平台消息时间不再被误用为执行超时依据。

## 4. Core Flow After The Change

```text
Publish 入事件
  → PG主键去重
  → 首次写入才非阻塞Notify
  → 消费方定时轮询 + ClaimPending
  → SKIP LOCKED领取，返回queued + Stage + Owner/Version

schedule
  ├─ 不回复 → Mark skipped，释放
  ├─ 需等候 → Defer retry_at，释放，到期再领取
  └─ 接受 → CreateClaimed原子写Task + generate

generate
  → Mark replying
  → 租约过期 → Recover queued/generate
  → 新Claim继续已有Task

sent / verify
  → 租约过期 → Recover retry/verify
  → 新Claim只进入核验/记账
  → Mark done
```

上述路径仅描述总线持久化协议；尚未装配真实采集、调度 worker 或平台发送。0.4 必须按阶段路由，0.8 还要落实投递前意图与未知结果补偿。

## 5. Key Code Concepts

**SKIP LOCKED**：多个消费者领取时，跳过其他事务正在锁定的行，而不是等待同一条事件。领取和换租在同一条 SQL 中完成，返回结果再按 At/ID 确定排序。会话串行仍是后续调度器的责任。

**租约与代次**：Owner 标识一次 Bus 实例，Version 标识一次持有权。每次重新领取、释放或恢复都递增代次。旧 worker 即使还拿着事件正文，也无法通过数据库的 Owner、Version 和未过期检查。

**状态时间与平台时间**：Event.At 是消息发生时间；StateAt 是当前状态开始时间；LeaseUntil 是允许当前 worker 持有的期限。续租不能重写 At/StateAt；很久以前的消息只要租约有效，就不能被当作崩溃恢复。

**阶段不是状态的别名**：queued 可以是在等待过滤、恢复生成或核验补偿。StageVerify 不能进入 replying，防止把已经发送的事件重新交给模型生成再投递。

## 6. Important Implementation Details

- 默认租期 5 分钟，合法 1 秒到 24 小时；领取和恢复每批 1–100。过期工作不因服务重启被无条件抢走，活跃租约必须继续受到保护。
- Notify 容量为 1，写满时合并；重复、失败和出事件不通知。消费者必须定期轮询和恢复，不能把通知数当成事件数。Bus 不关闭 channel，也不创建需要额外停止的后台循环。
- Mark 根据数据库真实状态与 Stage 判断，篡改 Claim 快照里的阶段不能取得新权限。延期必须用 Defer，并用 PG 时钟检查未来期限。
- CreateClaimed 和 stage 更新在同一事务内；任务 ID 冲突会整体回滚。对同事件重复创建，event_id 唯一约束只允许一份任务。
- 旧无租约入口同时要求 Owner 为空且 Version=0。仅检查 Owner 为空不够，因为延期/恢复释放后 Owner 也会为空；代次能证明它已经进入新协议。
- 续租需要“先锁行、再用另一条语句复检时间”。PG 的单条 UPDATE 时间谓词可能在等待行锁前就求值；如果锁等待跨过租期，直接 UPDATE 可能复活旧租约。本轮用真实 PG 先复现失败，再验证修复。
- v1 升级保留原 checksum，新增 v2 checksum；同一事务和迁移锁覆盖版本校验及升级。旧 replying 无法证明是否投递过，保守进入 verify，不能凭空假定可以重发。
- 公共业务库未执行迁移，未修改默认开关，也未调用模型/平台。使用新二进制前需要显式升级数据库；本轮仅在随机隔离 schema 验证。
- 判断器 v5、人设、知识数据及旧评估证据未改。0.2 旧快照保留，本轮对存储兼容入口的增量单独交付。

## 7. How To Verify

失败与修复证据在 `plans/reports/phase-0.3-event-bus/`：初次缺符号编译失败；typed-nil 构造失败；释放后旧入口绕过延期/核验的失败；锁等待跨到期续租失败。后续 GREEN、全仓检查与内部只读复核分别记录。补充覆盖测试有些直接验证既有实现，不宣称每个测试都单独经历 RED。

```powershell
go test ./... -count=1
go test -tags=integration ./... -count=1
go vet ./...
go build ./...
go run github.com/golangci/golangci-lint/v2/cmd/golangci-lint@v2.15.0 run --build-tags integration
wsl -e bash -lc 'cd /mnt/d/CodeStudy/RaiseMyFish && CGO_ENABLED=1 /usr/local/go/bin/go test -race ./... -count=1'
```

真实 PG 用例包括并发不重复领取、SKIP LOCKED、未来延期、有效租约保护、过期换租和旧 token 失效、阶段伪造、任务冲突回滚、有界恢复、v1→v2 升级/回滚/checksum。续租竞态测试先通过 pg_stat_activity 确认正在等待 Lock，再持锁跨过期限，不靠任意 sleep 猜并发顺序。

内部审查提出的两项 Important 已修复并复核；DSH 独立验收仍单独进行。普通 race 与真实 PG 集成是两条验证轨道，不能互相替代。
