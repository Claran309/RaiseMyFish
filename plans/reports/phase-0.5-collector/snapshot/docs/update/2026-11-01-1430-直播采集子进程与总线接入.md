# Change Note: 直播采集子进程与事件总线接入

## 1. What Changed

本次完成 Phase 0.5 的工程实现：将 `dsh-bili-whale@0.4.5` 的弹幕协议和 WS 监听移植到项目自己的 `tools/bili-whale/`，用 Go 管理 Node 子进程，再经已有 Event Bus 幂等写入 PG。

新增可选的 live 采集配置与 fishd 装配，默认仍关闭。启用时只运行采集到 Bus，不消费模型任务、不发送弹幕。`fishd check` 只检查装配，不启动子进程或访问 B站。

0.2～0.4 已在 `9dd7fd5` 中推送，协作文档提交 `bb70277` 本轮也已同步远端；0.5 新功能另待 DSH 验收。

## 2. Why This Change Was Needed

原脚本依赖 DSH 配置、主目录凭据和文件队列，还在采集阶段决定谁值得回复。它实际默认轮询，实验 WS 分支每 25 秒轮换，不能直接当作本项目的常驻采集器。

现在 Node 只负责平台协议，Go 负责进程生命周期、重连和标准事件，总线负责持久化幂等，Scheduler 负责是否回复。这样采集不再与主人筛选、人设或 DSH 会话绑定。

稳定事件 ID 尤其重要：没有平台 ID 时明确报解析问题，不能用时间、正文哈希或未经验证的数组字段制造一个看起来可去重的 ID。

## 4. Core Flow After The Change

```text
显式启用 live，填写房间和自身UID
  → fishd构造Collector与已有PG Bus
  → Go直接启动Node（不经过shell）
  → nav确认Cookie账号，解析规范房间，获取WBI/弹幕服务器
  → WSS认证成功才输出ready
  → DANMU_MSG显式平台ID + 平台时间
  → JSONL进入Go
  → 校验房间/身份/字段，过滤自身，截断到4000字符
  → live:{规范房间}:{平台msg_id}
  → Publish参数化幂等写PG
```

网络中断由 Go 按指数退避重启子进程；鉴权或运行时错误暂停该通道。Publish 失败会停止采集并保留错误链；基础设施继续运行，等待人工处理通道后重启。外层取消会终止并等待 Node，不留下子进程。

## 5. Key Code Concepts

**采集与决策分离**：自身 UID 必须过滤；其余普通观众和重复消息都可以产出。重复由 PG 主键处理，广告、是否叫鱼、是否主人等回复决策归 Scheduler，采集器不重复实现这些策略。

**精确标识与 JSON 数字**：JS Number 无法精确表示所有平台长整数。Node 24 的 JSON reviver 使用原数字字面保留大整数，再以字符串传给 Go。ID 和时间同时限制原始类型，不能把数组 `[7]` 转成身份 `7`。

**双层取消与背压**：Node 负责 HTTP/握手/存活期限，Go 还约束启动和空闲时间。Go 输出 channel 及 Node stdout 缓冲都有边界；落库慢会产生背压，取消时每层都能退出。

**凭据最小化**：Node 只得到必要 Cookie/文件与最小运行环境，不继承 DB DSN、LLM Key、NODE_OPTIONS 等。Cookie 不在命令行、URL、事件 Meta 或日志里；平台原始异常也不会直接显示。

## 6. Important Implementation Details

- 使用 Node 24 标准库，无 npm 依赖。HTTP 只访问固定 B站 HTTPS API，拒绝重定向；WS 只允许平台 chat.bilibili.com 节点。
- Cookie 仅来自显式 `FISH_BILI_COOKIE` 或 `_FILE`；文件支持 Cookie 文本和旧 credentials JSON，限 64 KiB。不自动寻找主目录或 DSH 状态。
- `self_id` 必须匹配 nav 的登录 UID。配置可用房间短号，但事件 session/key 始终使用平台解析的规范房间。
- 仅采用显式 `id_str`/`dmid`，缺失则报错跳过；不采用时间/正文哈希或原脚本的未验证字段兜底。At 保留平台时间，Health.LastEventAt 则记录接收时间。
- Node 压缩输出、递归、包数及 stdout 有硬上限；Go 行读取上限与 Node 1 MiB 对齐。正文按 Unicode 字符截断为 4000，安全 Meta 标记原长度及截断，不保存任意平台对象。
- 重连为 1→2→4…最多60秒；连续失败默认8次后暂停，只有足够稳定的连接才重置连续失败。平台限流类别会保留；鉴权失败直接暂停，不尝试刷凭据。
- Health 使用锁提供快照；错误展示固定类别。取消/发布失败时等待采集结束；发布错误与采集退出错误通过 Join 同时保留。
- `fishd check` 展示 enabled/configured/process_started/pipeline_connected；configured 只表示静态配置通过，不证明 Node 版本、Cookie 有效或平台可连接。
- 默认 `channels.live.enabled=false`。启用时仍只到 Bus；模型消费、发送、核验及 out 事件尚未装配。

```powershell

wsl -e bash -lc 'cd /mnt/d/CodeStudy/RaiseMyFish && CGO_ENABLED=1 /usr/local/go/bin/go test -race ./... -count=1'
```

Node 为 17/17；Go collector/live 覆盖率 79.8%，桥接 73.1%，config 92.0%，fishd 83.1%。PG 使用随机隔离 schema，Node 只输出合成事件：自身消息过滤、同 ID 重复只落一行、长 ID 不变、llm_usage 仍为0；另验证 fishd 启用采集/停止和 check 不启动标记脚本或写 status。

已有 RED/GREEN 包括缺模块、600000 字正文跨语言上限、限流分类、发布收尾错误链；内部助手还先用身份/时间非标量反例失败，再修复，主线程独立复跑最终 Node 全集。内部规格/质量审查通过，不代替 DSH。

**未验证真实房间的消息 ID、长连、断线或离线补漏。** WS 本身不能补齐进程离线时的全部消息；不搬源脚本的不可靠历史 ID 兜底，也不把合成组合测试当真实平台证明。整个 Phase 0 的两小时/不漏门槛仍需后续单独验收。
