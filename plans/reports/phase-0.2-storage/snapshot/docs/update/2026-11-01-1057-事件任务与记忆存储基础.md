# Change Note: 事件、任务与记忆的存储基础

## 1. What Changed

新增 Phase 0.2 存储接口及 PostgreSQL 实现：事件可以幂等写入、精确读取并按合法边更新状态；同一个入事件只能创建一个初始任务；记忆查询在 SQL 中过滤私密数据。已有 UsageRepo 继续负责 LLM 用量账本。

这是存储功能与测试的新增。尚未接入 fishd 业务循环，采集、总线领取、调度、发送、记忆提炼仍按后续任务推进。

## 2. Why This Change Was Needed

现有迁移已经建好了表，但业务模块不能直接到处写 SQL。没有统一存储入口时，重复采集可能覆盖原事件，并发调度可能创建多个任务，记忆查询也容易忘记隐私条件。

现在接口在 store，GORM/pgx 实现在 database，由调用方注入连接。数据库唯一约束解决并发去重，条件更新解决陈旧状态覆盖，范围查询解决私密隔离。本轮复用既有表，避免提前设计恢复租约和平台发送协议。

## 4. Core Flow After The Change

```text
可信调用方构造 Event
  → EventRepo.Insert
  → 校验通道、私密性、正文、初始状态
  → INSERT ... ON CONFLICT(id) DO NOTHING

事件已处于 queued
  → TaskRepo.CreateForEvent
  → 事务内 SELECT ... FOR UPDATE
  → 检查入事件及相同通道/会话
  → 利用 tasks(event_id) 唯一索引创建任务

可信调用方给出目标 Scope
  → MemoryRepo 的 Recent / CrossChannel / Records
  → SQL 隐私条件 + 排序 + 上限
  → 转为不含 Meta / Body 的最小 DTO
  → 再做 DTO 校验
```

queued 从何而来仍由 0.3 领取协议负责；本图没有表示总线或 worker 已经运行。

## 5. Key Code Concepts

**幂等写入**：同一个稳定事件 ID 重复到达，只保留第一次记录。不是先查再插，而是让 PostgreSQL 的主键约束在并发时决定唯一赢家。第二次调用返回 `inserted=false`，原正文及后续状态不被覆盖。

**CAS 条件更新**：更新状态必须同时匹配 ID 和调用方声明的旧状态。假设两个调用方都认为事件是 pending，只有第一个更新成功；另一个得到 Conflict，而不是覆盖新状态。调用方提供的每条 from→to 边还必须符合 Event 契约。

**事务与行锁**：创建任务前锁住事件行，检查它仍是 queued 入事件且范围相同。事务之外的并发状态更新会等待锁；event_id 唯一索引进一步防止重复任务。这里不把“写入任务”解释为“开始生成”。

**SQL 查询层隔离**：公开 Scope 强制 NOT private；私密 Scope 只能读取自己的私密会话。CrossChannel 无论目标是否私密，都只读取其他通道的公开行。DTO 校验是额外防线，不能替代 SQL 条件。

## 6. Important Implementation Details

- 入事件初始状态只能是 pending；出事件只接受 done/retry/dead，防止出事件误入采集调度。正文按 Unicode 字符限制在 4000 内；存储拒绝超长输入，后续采集器负责按约定截断和标注。
- EventRepo.Get 是可信内部的按 ID 精确读取，不能用它绕过面向模型上下文的 MemoryRepo 范围查询。
- 初始任务优先级限 0–3；Task 的后续领取、执行状态与发送补偿尚未实现。
- 查询上限为 1–100。最近消息先按时间/ID 倒序取最新 N 条，再按升序交给上下文；摘要按重要性降序、ID 升序。未来生效、已归档、已有 valid_to 的摘要不会召回。
- DM 被旧数据错误标成公开时，查询仍排除它。QQ 同一会话的公开/私密行分别按目标 Scope 筛选；不同私密会话不会因名称相同而互通。
- PostgreSQL 的 TEXT[] 来源 ID 通过 JSON 参数转换写入，读取时转 JSON 解码，避免拼接数组内容。SQL 行使用平坦结构，防止 GORM 把 DTO 中的 slice 误当关联对象。
- 调用方可通过 errors.Is 判断三类业务错误。数据库错误保留原因链，但展示固定阶段文字，不展示正文、SQL 参数或连接信息；取消不会被误当成空结果。
- 未改迁移、UsageRepo、人格、知识、评分器与旧评估产物。未实现版本化、完整 Reader、提炼 worker、Claim/恢复，也没有真实模型或平台调用。
