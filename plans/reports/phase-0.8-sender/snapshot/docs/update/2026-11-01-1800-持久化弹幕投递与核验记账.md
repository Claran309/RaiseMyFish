# Change Note: 持久化弹幕投递、核验与唯一记账

## 1. What Changed

本次实现 Phase 0.8 发送器。主人先批准 P0-SEND-1，再更新 Sender/Event/Memory 契约：发送入口携带租约与可信 Scope，新增 deliver 阶段，生成后的回复先持久化，投递前记录未知尝试，核验后原子结清。

移植的 `tools/bili-whale/danmaku.mjs` 只预检、单次 POST、只读核验。Go Service 管理令牌和恢复，PG 是 send_log/out 的唯一写入路径。默认发送关闭，fishd 仍未启动模型到发送的生产闭环。

## 2. Why This Change Was Needed

HTTP 超时不等于平台未收到。如果先发送、再写账，进程可能在中间退出，重启后会重复发送。原脚本的本地防重/outbox 也不能与 PG 事件、租约和记忆保持原子一致。

本实现先持久化固定回复与许可，才授权 Node POST。许可发出后结果未知就只核验，不用“没查到历史”推断未发送。它优先避免重复投递，不宣称平台不支持的 exactly-once；未知耗尽时保留人工处理状态。

## 4. Core Flow After The Change

```text
Brain已有回复（replying/generate）
  → Prepare：持久化固定正文、ready尝试、初始send_log/out
  → deliver（已有回复，恢复不重新调模型）
  → Node只读预检并ready
  → Arm：PG租约/账号/间隔/防重检查
  → 原子写许可 + 未知审计 + verify阶段
  → Go只写一次commit，Node最多一次POST
  → 强成功证据 → input done + out done + send_log verified
  → 可信否定/确定未commit → 有界deliver重试
  → 结果未知 → 只读verify，不重投
  → 核验耗尽 → input dead/DLQ，out仍retry/unknown_manual
```

verify 失败不能返回“没发过”。如果 Node 被强杀而没有结果帧，Go 同样保守 unknown。memory 不再创建 out，只读取已核验的 out。

## 5. Key Code Concepts

**不可变发送计划**：同一个输入事件绑定账号、规范房间和正文。恢复读取它，不再让模型生成另一份回复；换正文或身份会拒绝。

**许可是一次外部效果边界**：PG 在 commit 前已经知道该尝试可能发出。即使原 worker 消失，新 worker 也只核验。POST 结果还要匹配最初 arm 的 Owner/Version，恢复租约不能冒充旧 POST 回执。

**两层同一发送许可**：x/time/rate 是本实例的快速预留，PG 按账号锁负责重启/竞争约束。PG 拒绝或确定没写 commit 时退款；核验不扣令牌。0.4 的 Task 准入桶不当作平台发送扣账。

**保守发送间隔**：实际 POST 可能晚于 arm，因此 PG 保护到“许可最晚起点+10秒”，而不只看准备时间。相同账号/房间/正文也防重10秒；manual 仍可能已投递，继续参与防重。

**审计与发言事实分离**：send_log/out 包含 ready、未知、失败、跳过，保证可追溯；只有 out done 可以进入记忆。输入 dead/人工处理不代表平台确定没收到。

## 6. Important Implementation Details

- live 公开事件与 Reply.Scope 必须匹配实际 PG 行；私密或错误 Scope 不写公开正文。正文1–40 Unicode字符，Actions必须空，Meta不作为授权也不下传平台。
- Node 只使用显式 Cookie/文件，Session 通过 WeakMap 隐藏秘密并绑定完整请求。没有 DSH gate、主目录状态、本地 outbox 或文件防重。
- 正文和许可走有界 stdin，不在命令行；ready 前零 POST。Go 保持 stdin 到 result，所有读写有超时，取消会终止并等待进程。
- 成功码0但没有稳定 ID 不等于 Verified。回读须匹配本账号、房间、完整正文与已知精确 ID；未知 ID 时才允许持久化随机 nonce 的平台回显。相同文本/时间接近不能替代证据。
- 每个 attempt 只有一条 send_log 和一个 `live:out:{room}:{attempt_id}`。结果、审计和输入事件释放租约同事务；故障全部回滚。
- 明确拒绝有界最多3次；核验最多3次。未知始终 verify，不重发，耗尽转人工。账本和 out 保留 unknown_manual。
- 错误固定安全文字，保留 errors.Is/As 原因链，Cookie/原始响应不进入错误文本或 JSON。普通启动错误不会伪装成 context.Canceled。
- 旧 0001/0002 原字节保留，业务库未自动升级。启用新二进制前需显式 `fishd migrate up`；本轮只在随机 schema 应用新迁移。
- 服务默认发送关闭，真实房间、平台回执/rnd形态、实际限流和两小时运行仍留0.11，不把模拟数据当真实发送。
