# Phase 5 · Web 面板

> 目标：不用翻日志就能判断「鱼活没活、在干什么、花了多少」。
> 先做观测面板，再做交互。

## 依赖

Phase 0–4。

## 范围

| 页面 | 内容 | 优先级 |
|---|---|---|
| 总览 | 各通道健康、今日收发、今日花费 | P0 |
| 事件流 | 最近事件（按通道/状态过滤） | P0 |
| 记忆 | 搜索、查看、删除、版本历史 | P1 |
| 成本 | 按天/通道/模型汇总 | P1 |
| 人格 | 当前包、切换、回归结果 | P2 |
| 配置 | 只读展示 + 关键开关 | P2 |

## 技术选型建议

| 选项 | 说明 |
|---|---|
| Go 后端 + 嵌入式前端（embed） | 单二进制，部署最简单 |
| 前端框架 | 任意（Vue/React/Svelte），不引入重型依赖 |
| 实时 | SSE 或 WebSocket（事件流） |
| 鉴权 | 本地 token，仅 127.0.0.1 监听 |

**先只读**：P5 不做写操作（除了人格切换和开关）。

## 任务清单

- [ ] 前端构建嵌入二进制

## 退出标准

1. 打开面板能 30 秒内判断系统是否健康
2. 事件流能定位「某条弹幕为什么没回」
3. 记忆能搜到、能删
4. 面板不暴露凭据

## 可选后续（不在本阶段）

Flutter PC 客户端：作为产品化形态，依赖本阶段的 HTTP API。
是否做由主人后续决定（ADR：开发期 Web 够用）。

## 风险

| 风险 | 应对 |
|---|---|
| 前端占用开发时间 | 只读优先，交互滞后 |
| 面板暴露敏感数据 | 仅本地 + token，敏感字段脱敏 |
