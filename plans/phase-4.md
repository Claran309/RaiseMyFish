# Phase 4 · 成本优化与可观测强化

> 目标：让系统「长期活着」：预算可控、失败可见、能复盘。
> 注：P0 已有最小版（日志/日报/心跳），本阶段做强化。

## 依赖

Phase 0–3（数据量与多通道运行）。

## 任务清单

### 4.1 预算体系
- [ ] 全局日预算 / 通道日预算 / 单次请求预算
- [ ] 超限行为：降级（换便宜模型/缩短上下文）或熔断
- [ ] `fishctl cost --today` 汇总

### 4.2 模型分级
- [ ] 路由/分类用最便宜模型或规则
- [ ] 记忆提炼批量 + 便宜模型
- [ ] 通道回复按档位路由

### 4.3 缓存
- [ ] 人格包前缀缓存
- [ ] 会话上下文前缀稳定（顺序不变）
- [ ] 梗库/人设内存缓存 + 热更新

### 4.4 可观测强化
- [ ] 失败率告警（10 分钟窗口）
- [ ] 通道健康面板（CLI）
- [ ] 日报增强：跳过原因分布、失败分类
- [ ] 告警渠道（可先日志 + 终端）

### 4.5 复盘
- [ ] 每周成本/效果对比报表
- [ ] 回归集通过率趋势

## 退出标准

1. 日预算可配置，超限自动降级/熔断
2. 失败率异常能在 10 分钟内被看到
3. 日报能回答「今天花了多少、为什么」
4. 模型分级生效（便宜模型承担大部分调用）

## 风险

| 风险 | 应对 |
|---|---|
| 降级影响体验 | 降级只在超预算时触发，且优先降记忆不降人设 |
| 缓存不稳定 | 固定上下文顺序，回归测试覆盖 |
