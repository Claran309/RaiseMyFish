## 1. 三方角色

| Agent | 工作 | 边界 |
|---|---|---|
| Codex | 首席开发；架构、核心实现、公共接口、依赖与技术裁决；Git 集成 | 不能以开发自测代替 DSH 验收；跨 Phase、改既有 ADR 仍需主人授权 |
| WorkBuddy | 已拆明边界的轻量开发 | 不独立设计状态机、隐私策略、恢复与记账协议；发现缺口交 Codex |
| DSH | 独立验收；协助主人向两位开发者派发/切换会话、转达交接；维护计划与协作文档 | 检查失败可退回；技术争议交 Codex。默认不承担模块开发 |

DSH 主会话/flash 是同一角色的执行方式，不增加第四个决策层。技术裁决不意味着可以跳过失败的测试或缺失的验收证据。

主人的最新指令优先；AGENTS 是工程硬规则，contracts 是接口真源。分工和提示词不能放宽两者及 Phase 退出标准。文档互相矛盾时先登记 Phase「待定」，不能选择方便的示例直接实现。

## 4. 共享工作区与 Git

1. 默认共享工作区按精确路径协作；**仅 Codex 执行 Git 写操作**（包括 add/commit/pull/checkout/merge/push）。其他 Agent 可只读查状态和差异。保留个人项目直接 push master/main/dev、不走 PR 的约定。
2. 不并行 go mod tidy、全仓 gofmt -w .、切分支或修改共用测试库。开发者只格式化获派文件，依赖变更提交 Codex。
3. 集成窗口由 DSH 协助确认相关写入者已暂停，记录验收快照；没有回执不能当作已暂停。Codex 仅暂存本次验收覆盖的明确路径，禁止 git add . 混入别人的工作。
4. 开发自测 → DSH 对确定快照独立验收 → Codex 核对差异并提交 → DSH 确认提交对应验收快照 → Codex 直接 push。快照后有变化就重核/重验；远端更新先保全本地工作，再整合验证，不强推。
5. 需要独立 checkout 时，由 Codex 先明确基线、路径、负责人和集成方式再启用。会话中断不自动收回任务；DSH 核对原写入者暂停与现有改动后再重新分派。

## 5. 验收与状态维护

开发者在自己的报告追加：任务/子任务、基线/快照、获派及实际变更路径、接口影响、测试命令与结果、未执行项及原因、风险、是否已暂停写入。DSH 独立复核并更新看板和 Phase 任务勾选，不只转抄「全绿」。

功能门禁按 docs/testing.md：格式、lint、vet、race、build；关键数据库路径用真实 PG，不用 sqlite。缺工具/环境记阻塞或未验证；go vet 不能替代 lint，mock 不能证明真实目标模型人格通过率 ≥90%。文档交付用链接、规则一致性与差异检查，不要求为纯文档改动制造功能测试。

单项完成与 Phase 退出分开记录。真实直播 2 小时、重启不漏不重、人格 ≥90%、日报、30 分钟静默告警等退出标准仍逐项验收；不能因为某个子任务尚未达到整阶段标准就否认已完成的单项证据。

## 5.5 放权边界（2026-11-01 主人授权）

为避免「文档/流程束缚强模型」，在既有契约与安全边界内给 Codex 更多自主空间：

1. **范围明确后自主推进**：一个子任务获派后，实现细节、测试策略、小重构、错误信息措辞自己定，不逐步请示。
2. **只在四种情况请示**：① 改契约（导出符号/错误语义/Scope 映射）；② 越出允许路径；③ 花钱或真实模型调用；④ 安全边界（凭据/冒认/承诺/隐私）。
3. **探索性任务允许先做再评**：调参、人格微调、判断器边界这类探索，不强制严格「先红后绿」；但交付时必须说明实际顺序与发现的问题。
4. **判断器 v5 定稿**：安全硬线唯一失败条件、风格仅观察；不再迭代 v6，除非主人明确要求。
5. **护栏不变**：契约真源、旧证据保留、不越权写、DSH 独立验收、双轨验证仍必须遵守。
6. 本授权不改变 AGENTS 硬规则、Phase 退出标准与 Git 写权限（仍仅 Codex）。
