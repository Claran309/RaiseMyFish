# Super-agent 对齐与演进计划

> 2026-10-31 主人分享 [DeepSeek Super-agent 设计探索](https://m.ithome.com/html/1020615.htm)，
> 要求据此反思并修正开发计划。本文件记录对照结论、阶段映射与演进原则。
> 文章原文是外部资料，仅作参考；本文件是项目自己的决策。

## 1. 判断

- **目标形态**：RaiseMyFish 是 super-agent 的**单主体实例**——一个「肥鱼」通过多通道连续交互、并行处理多项任务、持续在线。
- **当前形态**：事件驱动的**单会话多通道 Agent**（Collector → Event Bus → Scheduler → Brain → Sender），每个事件独立处理，没有全局编排层。
- **原则**：按项目节奏演进，不因文章一次性堆架构。P0 只补「全局上下文」最小切片（Presence），Router/Worker 等单机规模需要时再拆。

## 2. 四特征对照

| Super-agent 特征 | 养鱼现状 | 阶段 |
|---|---|---|
| 连续（多渠道同一 Agent） | ✅ 直播/评论/私信/QQ | P0/P1 |
| 高效（并行多任务） | ⏳ 多通道并行采集；Brain 串行 | P1 起 |
| 主动（观察事件自主推进） | ⏳ 评论巡逻（P1） | P1 |
| 持久（在线 + 异常恢复） | ✅ PG + 状态恢复 + 心跳 | P0 |

## 3. 五组成映射

| Super-agent 组成 | 养鱼对应 | 阶段 | 说明 |
|---|---|---|---|
| **Router + Worker 双层** | ❌ 暂无；当前是平面管道 | **P6.5（新增）** | 单机单主体时不需要；出现「多会话并行 + 全局上下文」需求时再拆 |
| 事件驱动（Trigger/Thread） | ✅ Event Bus；❌ Thread 概念 | P1（Thread） | 评论巡逻同一话题连续事件归组 |
| 全局上下文（Inline & Spill） | ❌ 暂无；Presence 是第一块 | **P0.6 Presence** | 主体状态表；后续可扩展为全局上下文 |
| Chain of Recall（引用链召回） | ❌ 暂无（召回平铺） | P2（2.12） | 沿 Trigger/Thread/记录引用找回历史 |
| 面向人的交互 | ✅ 多通道 | P0/P1 | 一致 |
| 计算/状态/环境解耦（BYOM） | ❌ 单机 fishd | P7+（可选） | 云端算 + 本地 daemon；单机不是问题 |
| Watchdog（独立监控） | ❌ 暂无（0.10 只有指标） | P0.10 雏形 → P4 加强 | 调度器心跳/超时检测卡死，先不做独立会话 |
| 异步工具（start/stop） | ❌ 暂无（P0 单次调用） | P6（6.5） | MCP 工具接异步语义 |
| 投机执行 | ❌ 暂无 | P7+（可选） | 会议邀约类的提前准备；养鱼场景有限 |

## 4. 阶段修正

| 阶段 | 新增/修正 | 依据 |
|---|---|---|
| P0.6 | **Presence 三心二意状态表**（已规划） | 全局上下文最小切片 |
| P0.10 | Watchdog **雏形**：调度器心跳/超时检测（不建独立会话） | Watchdog 轻量版 |
| P1 | **Thread 概念**：同话题/同帖连续事件归组，Worker 订阅 Thread | 事件驱动增强 |
| P2 | **引用链召回（2.12）**：记忆记录带 Trigger/Thread 引用，沿链找回 | Chain of Recall |
| P4 | Watchdog 加强：卡死/偏离检测 | Watchdog 正式版 |
| P6 | **异步工具（6.5）**：工具 start/stop 语义，结果作为新事件 | 异步 ReAct Loop |
| **P6.5（新增）** | **编排层**：Router/Worker 拆分（多会话并行、全局上下文） | 双层架构；单机规模够了再拆 |
| P7+ | BYOM / 投机执行（可选） | 按需 |

## 5. 不做什么

- ❌ 不在 P0 引入 Router/Worker 双层（过度设计）
- ❌ 不把 Presence 做成完整全局上下文（先最小切片）
- ❌ 不因文章改变现有事件/记忆/人格的契约边界
- ❌ 不引入新的分布式组件（仍是单机单库）

## 6. 验收与复核

- P0.6 Presence 验收后，复核「全局上下文」是否够用，再决定是否扩展
- P1 Thread 落地后，评估评论巡逻的并行效果
- P6.5 编排层作为独立放行点，需要主人明确批准
