# RaiseMyFish · 养鱼框架（多通道 AI 陪伴体 · 稳定版开发中）

> 一条 AI 肥鱼的多通道陪伴系统：**看直播、回弹幕、回评论、回私信**，
> **有长期记忆、有知识库（RAG）、能自主查证（ReAct）、有可视化面板、能自愈**。

---

## 一句话定位

> **一个事件驱动的、多通道、带人格与记忆的 super-agent（单主体实例）。**

一个「肥鱼」主体——Persona（怎么说）+ Presence（在做什么）+ Memory（记得什么）+ Knowledge（知道什么）——通过直播/评论/私信多通道持续在线、并行回复；会话无状态，每次回复完即散。

**与旧方案（agent 会话式蹲播）的区别**：延迟从 30-40 秒降到 1 秒级；记忆从「会话上下文」变成「结构化库 + 向量召回」；从脚本堆变成可观测、可自愈的工程。

## 能力矩阵

### 🎙️ 多通道

| 通道 | 采集 | 回复 | 状态 |
|---|---|---|---|
| **直播弹幕** | WS 实时（danmaku-await） | 1 秒级 + ReAct | ✅ 生产可用 |
| **评论** | 自动发现自己账号的视频/动态 → 轮询评论区 | 回复每个评论 | ✅（默认关） |
| **私信** | 全收（所有发信人） | 回复每个发信人 | ✅（默认关） |

统一 `Channel` 接口 + 注册表；调度器（五道闸）+ 事件状态机（pending→queued→replying→sent→done）+ 租约。

### 🧠 记忆与知识

| 层 | 实现 |
|---|---|
| 事件 | events 全量（11k+ 历史迁移） |
| 提炼 | 规则 + LLM（高价值事件）+ fact/preference |
| 观众档案 | 209 人（谁说过什么/鱼怎么回） |
| 灵魂记忆 | 设定级（每轮注入 `<longterm>`） |
| 知识库 | 7339 条梗（K0 文件 + **pgvector 向量**） |
| 语义召回 | 关键词档位 + α×余弦混合；谐音梗靠 keywords 兜底 |

### 🤖 思考与工具

| 能力 | 实现 |
|---|---|
| 两段式 → **默认 ReAct** | 所有弹幕走 ReAct（短句 <6 字单步）；5 分钟缓存 |

### 📊 运维与自愈

## 架构（数据流）

```
采集器（WS/node/轮询）
  → 事件总线（PG + 租约）
  → 调度器（五道闸：ACL/噪音/幂等/节流/会话锁）
  → Brain（人格 + 记忆召回 + 知识 RAG + ReAct）
  → 发送器（danmaku/评论/私信，原子结清）
  → 事件状态机 → 观测/面板
```

**边界**：不引入 Redis/MQ/Milvus（单机多进程 + PG 足够）；外部依赖（danmaku/gift/ASR/embedding）可配、可降级。

## 快速启动

```bash
# 1. 依赖：PostgreSQL 17（pgvector）、Node 24、Go 1.25+（仅构建）
# 2. 配置：config/fishd.toml + .env（cookie/LLM key/embedding key）
# 3. 迁移：bash scripts/migrate.sh
# 4. 启动：bash scripts/test-run.sh（或 go run ./cmd/fishd --env-file .env）
# 5. 面板：http://127.0.0.1:8090

# Docker（Linux/服务器）：
cp .env.example deployment/.env   # 填凭据；DSN 主机用 postgres
# 首次启动前核对 config/fishd.toml 的房间/账号/礼物开关
make docker-up                     # fishd + pgvector/pgvector:pg17，自动迁移
```

部署方式与依赖细节见 `docs/13-deployment.md`。
